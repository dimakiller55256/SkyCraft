# Автоматические тесты SkyCraft

**Архивная инструкция network.3. Для нового второго прогона используйте
[YS-RETEST.md](YS-RETEST.md) или АВТОТЕСТЫ.html из комплекта network.4.**

Нужен новый Java-мод **0.1.2-ys.network.3**. Нативная DLL остаётся 0.1.2.
Комплект запускается в Windows через обычный двойной щелчок; Python, Java SDK
и дополнительный аккаунт для помощника не нужны. Minecraft использует свою Java 25.

## Первое открытие

1. Распакуйте **весь** ZIP в отдельную папку вне Skyrim. Не запускайте EXE из окна архиватора.
2. Откройте **SkyCraft-Без-друга.exe** (или файл нужной роли). Проверьте поле
   Minecraft: это папка с `mods`, `config`, `logs`. Помощник ищет экземпляры Prism
   в обычных каталогах и запоминает выбранную папку. Если экземпляров несколько,
   выберите используемый SkyCraft. При необходимости: Prism → экземпляр SkyCraft →
   Папка Minecraft → скопировать путь или кнопка «Выбрать папку» в помощнике.
3. Закройте Skyrim и этот экземпляр Minecraft обычным способом. Нажмите
   **«Обновить мод»** один раз. Старый JAR сохранится в `SkyCraft-YS-backups`
   рядом с экземпляром; аккаунты, миры и файл `skycraft.properties` сохраняются.
   Другие запущенные проекты не останавливаются. Если обновление отказало,
   прочитайте сообщение: игры должны быть закрыты; повторите после закрытия.
4. Запустите Skyrim как обычно через **MO2 → SKSE** и загрузите **отдельное
   тестовое сохранение после Хелгена**. Главное меню недостаточно. Не сохраняйте
   поверх основного сохранения. Вернитесь к окну помощника через Alt+Tab.
5. Поле Skyrim должно указывать на папку `SkyrimSE.exe`. Оно ищется автоматически;
   исправьте кнопкой «Выбрать», если найден другой экземпляр. Если MO2 хранит моды
   вне `Skyrim/Mods`, установочный отчёт может показать WARN для нативного плагина;
   сетевые тесты продолжатся, а галочки MO2 этим не проверяются.

Помощник работает только с выбранным экземпляром. Сначала обновите мод на обоих
ПК: старая network.2 не принимает автоматические команды.

## Без друга: один ПК

1. Откройте **SkyCraft-Без-друга.exe**, выполните первое открытие выше.
2. Выберите **«Без друга»**, транспорт оставьте «Как в настройках SkyCraft».
   Поле кода подключения оставьте пустым. Нажмите **«Начать автотест»**.
3. Дождитесь окончания. Помощник сам запускает логгер, проверяет реальные
   DIRECT/SOCKS5/HTTP CONNECT сокеты и отсутствие обхода недоступного прокси,
   открывает собственный мир, проверяет его TCP-порт, выбирает закрытый локальный
   порт, выполняет неудачный вход и ждёт восстановления мира. Затем повторно
   открывает мир и проверяет DIRECT. Команды в чате и редактирование properties
   не нужны. Этот прогон может временно переключить мир Minecraft: именно так
   воспроизводится восстановление S02. В мире не должно быть других игроков.
4. Нажмите **«Открыть отчёты»**. В открытой папке будут каталог прогона и
   готовый ZIP с таким же именем. Для передачи разработчику нужен именно ZIP.
   Итоговый текст находится внутри в **ИТОГИ.txt**.

Координаты до/после и около переходов записываются для SKY-001. Автоматическая
проверка восстановления не объявляет смещение нормой и не устанавливает его причину.

## Хост

1. Откройте **SkyCraft-Хост.exe**, загрузите тестовое сохранение по пунктам первого открытия.
2. Если вы с другом в одной Wi-Fi/Ethernet-сети, выберите **«Одна локальная сеть»**.
   Иначе оставьте **«Разные сети»**. Нажмите **«Начать автотест»**.
3. Помощник сам откроет мир на TCP 25565 (если мир уже опубликован, использует
   его фактический порт), соберёт IPv4/IPv6 и проверит локальный TCP.
4. Когда появится код **SCY1:…**, нажмите **«Копировать код хоста»** и передайте
   весь код другу привычным способом. Ничего вычислять и выписывать по IP не нужно.
   Код действует 24 часа и содержит адреса и порт; после изменения сети создайте
   новый прогон и новый код. Для ручного внешнего порта/домена пока используйте
   подробную инструкцию YS-TESTING.md; автоматический код использует порт игры.
5. Не закрывайте Skyrim. Помощник ждёт клиента до 20 минут и после обнаружения
   двух игроков записывает три минуты состояния соединения. Пока он наблюдает,
   можете вместе проверить движение и блоки на тестовом мире. Хост остаётся открыт
   после окончания теста; закройте игру обычным способом, когда закончите.
6. Получите ZIP кнопкой **«Открыть отчёты»**. Если клиент не пришёл, нажмите
   **«Остановить и собрать отчёт»**: уже полученные данные сохранятся.

## Клиент

1. Откройте **SkyCraft-Клиент.exe** и загрузите своё тестовое сохранение со SkyCraft.
2. Вставьте весь код **SCY1:…** хоста в большое поле. Выберите тот же вариант сети:
   одна LAN или разные сети. Настройку транспорта по умолчанию помощник берёт
   из **вашего** SkyCraft; для первого прямого прогона можно выбрать DIRECT.
3. Нажмите **«Начать автотест»**. Помощник проверит адреса из кода через выбранный
   транспорт, возьмёт первый доступный, выполнит вход, запишет три минуты состояния,
   вернётся в свой мир и повторно войдёт к хосту с 15 секундами наблюдения.
   Убедитесь, что это отдельное тестовое сохранение: прогон включает выход и вход.
4. После окончания клиент остаётся в мире хоста. Возврат для обычной игры:
   `/leave` в игровом чате. Отчёт уже собран; нажмите **«Открыть отчёты»** и передайте ZIP.

Оба отчёта имеют общий ID из кода хоста, поэтому их можно сопоставить без ручного
ввода идентификатора. Пинги, моменты входа, ошибки TCP/прокси, число игроков,
наличие связи Skyrim, версии и сведения Windows собираются автоматически.

## VPN, прокси и адреса

Для очередного варианта сами включите/выключите zapret, Cloudflare или VPN
в их обычных интерфейсах, затем повторите прогон. Помощник не переключает
эти программы и не принимает наличие процесса за доказательство активного режима.
Отчёт сохраняет снимок процессов, адаптеров, DNS, маршрутов и системного прокси.
Укажите разработчику, какие программы и режимы были включены: это факт, который
нельзя надёжно вывести только из присутствия адаптера.

В списке транспорта можно выбрать DIRECT, SOCKS5 или HTTP_CONNECT.
Поле справа — адрес **вашего прокси**, например `127.0.0.1:8080`, а не адрес хоста.
Для HTTP помощник подсказывает обычный системный прокси, если его адрес найден
в Windows; PAC-скрипт автоматически не исполняется. SkyCraft сам по себе не
следует системному прокси. Логин/пароль из существующих настроек используются
только для того же адреса прокси и не попадают в отчёт. Выбор транспорта действует
до завершения текущей сессии помощника; постоянный файл настроек не переписывается.

Галочка внешнего IP делает HTTPS-запрос к [ipify](https://www.ipify.org/)
для IPv4 и, при отказе, повторяет через универсальный IPv4/IPv6 endpoint;
без системного HTTP-прокси. Это адрес выхода текущего маршрута, который при VPN
может принадлежать VPN, и **не доказательство входящей доступности**. Можно
снять галочку: локальные адреса и глобальный IPv6 всё равно будут найдены.
В режиме «Разные сети» клиент не пробует частные LAN-адреса; в LAN пробует их.
Адреса обнаруженных Radmin/Hamachi/WireGuard/WARP помечаются как кандидаты
виртуальной сети. Они пробуются только при выборе «Общая виртуальная сеть»;
оба игрока должны уже состоять в этой сети. Это не установка зависимости
и не требование стороннего аккаунта для помощника.

Если все адреса недоступны, отчёт содержит BLOCKED с причиной. Брандмауэр,
CGNAT, отсутствие проброса порта или запрет входящих соединений VPN нельзя
исправить повторным поиском IP. Помощник не меняет маршруты, DNS, брандмауэр
или роутер. Для Интернета по IPv4 нужен доступный входящий TCP-порт; по IPv6 —
разрешение входящего TCP. Ретранслятор для закрытого NAT пока не реализован.

## Отчёт и смысл результатов

Папка по умолчанию: `%LOCALAPPDATA%\SkyCraft\TestAssistant\reports`.
Кнопка **«Открыть отчёты»** открывает её; искать AppData вручную не требуется.
Каждый запуск создаёт отдельную папку и ZIP; старые результаты сохраняются.
В ZIP — ИТОГИ.txt, automatic-results.json, адреса, наблюдения, проверка установки
и отдельный сетевой архив с исходным JSONL. Пароли, аккаунты, сохранения,
содержимое пакетов и полные игровые логи автоматически не включаются.
Отчёт не отправляется в Интернет. Запрос внешнего IP — отдельное действие выше.

PASS ставится **конкретному измеренному факту**. TCP PASS не доказывает вход,
вход PASS не доказывает HUD/движение/блоки. Пропущенные графические проверки
имеют NOT_RUN, остановленное наблюдение — PARTIAL, недоступные условия — BLOCKED.
В paired-тесте три минуты относятся к соединению Minecraft; доля связи Skyrim
указывается отдельно, потому что Alt+Tab может временно приостанавливать Skyrim.

Для воспроизводимости локальная связь помощника использует только файлы
`MINECRAFT/config/skycraft-test`: lease.json, request.json, state.json.
Управление включается короткой сессией, которую помощник продлевает раз в две
секунды. При закрытии/сбое она истекает максимум через 15 секунд, временная
настройка транспорта снимается. Не копируйте эти файлы между компьютерами.
Помощник не запускает Skyrim автоматически и не нажимает загрузку/сохранение за игрока.

## Проверки разработчика

Java: JUnit и изолированный настоящий Minecraft smoke с файловыми командами,
реальными TCP-проверками, временным выбором DIRECT и восстановлением HTTP CONNECT
после удаления сессии. Отдельный настоящий мир Minecraft проверяет публикацию,
TCP, закрытый порт, неудачный вход, восстановление и повторное открытие хоста;
папка `.tools/assistant-world-smoke` изолирована от установленных миров.
Windows: сборка EXE, проверка IPv4/IPv6-кода,
отказа устаревшему/неправильному коду и второй сессии, очистки lease, интерфейса,
пакетного обновления и сборщика на изолированных экземплярах.
Прохождение этих проверок не заменяет запуск двух реальных Skyrim на двух ПК.
