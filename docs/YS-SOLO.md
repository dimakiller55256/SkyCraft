# SkyCraft: проверка без друга

**Для network.6 начните с [YS-GAMEPLAY.md](YS-GAMEPLAY.md), раздел «Проверка без друга».
Ниже остаются дополнительные ручные сетевые сценарии. Для нового комплекта
нужно обновить JAR и SkyCraft.dll; указания о прежних network.3 не означают,
что обновление до network.6 можно пропустить.**

Готовая последовательность для одного ПК: S01_01 → S02_01 → S03_01 (SOCKS5) → S03_02 (HTTP CONNECT) → S01_02 (возврат DIRECT). Сначала прочитайте G1–G8, затем выполняйте B0–B10 по порядку. B11 — необязательный тест разработчика. Второй игрок и сторонний сетевой аккаунт для этой последовательности не нужны.

Начните с G1–G8: там найден путь файла, способ сохранения и объяснение команд. Все CMD запускаются из распакованного комплекта. MINECRAFT обозначает полный путь из Prism; он не вставляется в команду буквально.

[Таблица Excel](testing/SkyCraft-Network-Tests.xlsx). [Проверка без друга](YS-SOLO.md).

## Пути, файлы и ввод команд

### G1 — Найти папку Minecraft

**Что сделать:**

1. Откройте Prism Launcher, которым SkyCraft запускает Minecraft.

2. Нажмите правой кнопкой на используемом экземпляре SkyCraft → «Папка Minecraft» (Minecraft folder). Откроется Проводник.

3. Нажмите Ctrl+L в Проводнике, затем Ctrl+C: скопируется полный путь. Запишите его в отдельный текстовый файл. В этой инструкции этот путь обозначен словом MINECRAFT.

4. Проверьте, что внутри есть папки mods, config, logs. Название последней папки может быть minecraft или .minecraft; выбирайте фактическую, не переименовывайте её.

**Что проверить:**

Например, если Проводник открыл D:\PrismLauncher\instances\SkyCraft\minecraft, то файл настроек находится в D:\PrismLauncher\instances\SkyCraft\minecraft\config\skycraft.properties. Это пример установки; друг берёт путь из своего Prism. Папка экземпляра с instance.cfg находится на уровень выше и для поля «Каталог Minecraft» не подходит.

### G2 — Открыть нужный файл настроек

**Что сделать:**

1. Закройте Skyrim через меню выхода. В Prism убедитесь, что именно экземпляр SkyCraft больше не запущен. Если он остался активен, используйте кнопку остановки этого экземпляра. Другие Java-программы не закрывайте.

2. В папке из G1 откройте config. Найдите skycraft.properties.

3. ПКМ по skycraft.properties → «Открыть с помощью» → «Блокнот». Если расширение скрыто, в Проводнике включите «Вид → Показать → Расширения имён файлов» (Windows 11) или «Вид → Расширения имён файлов» (Windows 10).

**Что проверить:**

Все параметры join и network.* редактируются в MINECRAFT\config\skycraft.properties. SkyCraft.ini в моде MO2 управляет запуском и этими параметрами сети не заменяется. Если файла нет, запустите SkyCraft через SKSE/MO2 до HUD, выйдите из обеих игр и проверьте папку снова. Если файла всё ещё нет — сначала соберите отчёт запуска по R1, не создавайте наугад файл в другой установке.

### G3 — Сделать копии до изменения

**Что сделать:**

1. Создайте папку backup внутри распакованного тестового комплекта вне Skyrim, например D:\SkyCraftTest\backup.

2. Скопируйте туда skycraft.properties из G2; назовите копию skycraft.properties.before-tests.

3. Перед проверкой /join или блоков при закрытых обеих играх скопируйте всю папку MINECRAFT\saves\SkyCraft в backup\SkyCraft-world-before-tests. Если мира ещё нет, он создастся при первом запуске. Skyrim проверяйте на отдельном сохранении, основное не перезаписывайте.

**Что проверить:**

Папка saves\SkyCraft — мир Minecraft, который SkyCraft открывает автоматически. Выбор другого сохранения Skyrim не создаёт новый мир Minecraft. Копии остаются у вас; в отчёт их не добавляйте.

### G4 — Изменить и сохранить строки

**Что сделать:**

1. В Блокноте ищите ключ через Ctrl+F, например network.mode=. Если он есть — замените всю его строку. Если отсутствует — добавьте строку в конец файла на новой строке.

2. Для каждого ключа оставьте только одну строку: повторяющиеся join= или network.mode= удалите, сохранив нужное значение. Строки, начинающиеся с #, являются комментариями.

3. «Пустое значение join» записывается буквально join=, без кавычек и без слова «пусто».

4. Нажмите Ctrl+S. Сохраните кодировку UTF-8 без BOM, если Блокнот предлагает выбор кодировки. Закройте Блокнот и откройте файл повторно: значения должны сохраниться, имя — skycraft.properties, без добавленного .txt.

**Что проверить:**

Пример готовой базовой конфигурации:

`join=`

`network.mode=DIRECT`

`network.hostPort=25565`

`network.advertisedAddress=`

`network.timeoutMillis=10000`

Остальные существующие строки оставьте. Эти пять строк редактируют файл, они не являются командами чата. Параметр timeoutMillis задаётся в миллисекундах: 10000 = 10 секунд.

### G5 — Применить настройки и запустить игру

**Что сделать:**

После редактирования по G4 заново запустите SKSE через MO2: в списке запускаемых программ выберите SKSE, нажмите «Запустить», загрузите тестовое сохранение после Хелгена и дождитесь HUD Minecraft. При каждой смене сетевого режима в этой инструкции выполняйте такой перезапуск. Не запускайте вручную второй SkyCraft одновременно.

**Что проверить:**

Перезапуск гарантирует применение join, который читается при запуске. Сетевые команды /join, /skycraft host и /skycraft netcheck также читают network.* перед действием. Если HUD/движение отсутствуют, переходите к отчёту запуска R1, сетевой тест пока не выполняйте.

### G6 — Куда вводить команды

**Что сделать:**

Команды, начинающиеся с /: окно Skyrim с загруженным сохранением → английская раскладка → T → вставить или набрать ОДНУ команду → Enter. Для следующей команды снова T. Escape закрывает чат.

Команды Windows: нажмите Win, наберите Windows PowerShell, откройте приложение. Вставьте ОДНУ приведённую команду и нажмите Enter. Для Get-/Test-команд права администратора и особая текущая папка не требуются. После проверки вернитесь в Skyrim через Alt+Tab.

**Что проверить:**

Стрелки → в старых описаниях означали порядок, а не часть команды; в новых шагах команды вынесены на отдельные строки. Если чат T не открывается, запишите этот факт и соберите R1. Не вводите /skycraft в консоль Skyrim, открываемую клавишей ~.

### G7 — Значения, время и номер попытки

**Что сделать:**

HOST_LAN_IP — IPv4 ПК хоста из A1; HOST_ROUTER — шлюз из A1; HOST_WAN_IP — WAN адрес из A4. HOST_PORT — внутренний порт, EXTERNAL_PORT — внешний порт роутера. ENDPOINT — готовая строка адрес:порт (для IPv6 [адрес]:порт). Эти обозначения заменяйте своими данными.

Run ID — ваше название попытки: L01_01, S01_01 и т. п. Следующая попытка того же сценария: L01_02. Для двух ПК ID одинаковый.

Текущее UTC-время в PowerShell:

`[DateTime]::UtcNow.ToString("yyyy-MM-ddTHH:mm:ssZ")`

**Что проверить:**

Время в событиях JSONL/events.csv уже записано как UTC. Московское время имеет UTC+3; записывайте UTC командой либо подписывайте свои наблюдения «МСК». Не вычитайте часы повторно из UTC лога. Начало прогона — первое событие environment (поле utc), а не время создания отчёта.

### G8 — Восстановить настройки

**Что сделать:**

1. Закройте Skyrim и его экземпляр Minecraft по G2.

2. Если хотите полностью вернуть прежнюю конфигурацию, скопируйте backup\skycraft.properties.before-tests обратно в MINECRAFT\config и переименуйте копию в skycraft.properties, подтвердив замену.

3. Если хотите сохранить базовый DIRECT для будущих тестов, вместо полного отката примените пять строк из G4.

4. Верните исходные состояния VPN, Cloudflare и zapret, записанные до тестов. Затем выполните G5.

**Что проверить:**

Копию мира восстанавливают только при необходимости и при закрытых обеих играх: сначала сохраните текущее MINECRAFT\saves\SkyCraft под новым именем в backup, затем скопируйте исходную копию обратно как MINECRAFT\saves\SkyCraft. Это возвращает изменения мира к состоянию копии; без нужды мир не заменяйте.

## Проверка одному по шагам

### B0 — Подготовка без друга

**Что сделать:**

1. Распакуйте новый комплект целиком вне Skyrim. Откройте эту инструкцию, таблицу и Блокнот для заметок.

2. Если network.3 уже установлен, повторная установка не нужна. Запустите «Проверить сборку.cmd»: путь Minecraft из G1, папка с SkyrimSE.exe, затем папка Mods вашего MO2 по подсказкам. Откройте полученный ПРОВЕРКА.txt по пути из программы. FAIL сначала разберите, WARN прочитайте.

3. Выполните G1–G5, включая копии и пять базовых строк G4. Запишите состояние VPN/Cloudflare/zapret; для первого прогона выключите их через интерфейсы программ.

4. Загрузите тестовое сохранение, проверьте HUD, WASD и камеру. В чате:

`/skycraft debug status`

**Что проверить:**

Всё делаете вы на одном ПК. Второй Skyrim, второй Minecraft, внешний IP, вход в роутер и проброс порта для B1–B10 не нужны. PASS этих тестов означает только их собственное ожидание; совместную игру в таблице оставьте NOT_RUN.

### B1 — S01_01: начать запись и открыть порт

**Что сделать:**

После свежего запуска G5 откройте Windows PowerShell по G6:

`Get-NetTCPConnection -State Listen -LocalPort 25565 -ErrorAction SilentlyContinue`

Если вывод пустой — порт свободен. Если строка есть — остановитесь, не закрывайте неизвестный процесс; для этих готовых команд сначала освободите порт завершением известного старого SkyCraft либо пришлите вывод. Вернитесь в Skyrim. В чате по одной команде:

`/skycraft debug start S01_01 host`

`/skycraft debug status`

`/skycraft host 25565`

`/skycraft debug mark HOST_READY`

**Что проверить:**

status показывает включённый логгер и путь с S01_01-host. Команда host отвечает «Мир открыт на порту 25565». Если «Мир уже открыт», для проверки host_open начните заново со свежего запуска G5 и нового ID S01_02. Ошибка порта/логгера — запишите её и соберите отчёт R2–R5.

### B2 — S01_01: проверить TCP на своём ПК

**Что сделать:**

В чате Skyrim:

`/skycraft netcheck 127.0.0.1:25565`

Дождитесь сообщения о доступном TCP. В Windows PowerShell:

`Get-NetTCPConnection -State Listen -LocalPort 25565 | Select-Object LocalAddress,LocalPort,OwningProcess`

`Test-NetConnection -ComputerName 127.0.0.1 -Port 25565 -InformationLevel Detailed`

Скопируйте вывод в заметки. Вернитесь в игру, походите 2 минуты, убедитесь, что HUD и ввод работают.

**Что проверить:**

Ожидается строка порта LISTEN, TcpTestSucceeded=True и в чате «TCP … доступен». 127.0.0.1 здесь является готовым адресом текущего ПК. Не выполняйте /join 127.0.0.1:25565: вход в себя закроет собственный сервер и не создаст второго игрока.

### B3 — S01_01: закончить и собрать отчёт

**Что сделать:**

Выполните R2. В мастере режима 2 по R3–R4 введите: ID S01_01; роль Host; сеть Loopback; адрес 127.0.0.1; порт 25565; фактические состояния программ; pass при выполнении B1–B2, иначе fail/partial с причиной. Notes: «S01; DIRECT; один ПК; LISTEN и TCP проверены; второго игрока нет».

Проверьте отчёт по R5 и заполните R6.

**Что проверить:**

В events.csv есть host_open, probe_result с tcp_ready и trace_closed. S01 может получить PASS; поля движения/блоков двух игроков и rejoin остаются NOT_RUN. Сохраните ZIP до следующего теста.

### B4 — S02_01: проверить отказ на закрытом порту

**Что сделать:**

1. Закройте обе игры по G2 и запустите их снова по G5 с базовыми строками G4. /host в этом тесте не выполняйте.

2. В PowerShell:

`Get-NetTCPConnection -State Listen -LocalPort 25566 -ErrorAction SilentlyContinue`

Пустой вывод = никто не слушает. Если есть строка, остановите этот тест, не отключайте неизвестную программу.

3. В чате Skyrim по одной команде:

`/skycraft debug start S02_01 client`

`/skycraft netcheck 127.0.0.1:25566`

Дождитесь отказа. При timeoutMillis=10000 обычно ответ быстрее 15 секунд; если ответа нет, запишите время и не запускайте следующую проверку поверх незавершённой.

**Что проверить:**

Ожидаемый результат — отказ соединения, игра остаётся управляемой. Это намеренно неправильный адрес порта; появление ошибки здесь является успешной проверкой обработки ошибки.

### B5 — S02_01: проверить восстановление своего мира

**Что сделать:**

После ответа netcheck в том же чате:

`/join 127.0.0.1:25566`

Подождите возврата в свой Minecraft-мир. Запишите сообщение и длительность. Сеть должна отказать; загрузка своего мира занимает дополнительное время. Если спустя 60 секунд HUD/управление не восстановились, запишите это как FAIL восстановления и соберите отчёт. После восстановления:

`/skycraft debug mark OWN_WORLD_OK`

Проверьте WASD и чат в течение 2 минут с начала B4, затем R2. Мастер: S02_01, Client, Loopback, 127.0.0.1, 25566; pass только если отказ и восстановление выполнены.

**Что проверить:**

В отчёте probe_result=failed; после /join ожидается return_to_own_world и затем world_join с result=local. Сохраните полный текст ошибки в Notes. Сеть в таблице: REFUSED или TIMEOUT по сообщению; сам сценарий может быть PASS.

### B6 — S03_01: настроить намеренно отсутствующий SOCKS5

**Что сделать:**

1. Сохраните отчёт S02. Закройте обе игры по G2.

2. В PowerShell повторите проверку 25566 из B4: вывод должен быть пустым.

3. Откройте MINECRAFT\config\skycraft.properties по G2. По G4 оставьте или добавьте строки:

`join=`

`network.mode=SOCKS5`

`network.proxy=127.0.0.1:25566`

`network.proxy.username=`

`network.proxy.password=`

`network.hostPort=25565`

`network.advertisedAddress=`

`network.timeoutMillis=10000`

Сохраните и перезапустите по G5.

**Что проверить:**

Порт 25566 намеренно свободен; прокси на нём не запускаем. Пустые username/password нужны только этому отрицательному тесту. Реальные прежние значения находятся в копии G3.

### B7 — S03_01: проверить SOCKS5 без скрытого DIRECT

**Что сделать:**

В чате по одной команде:

`/skycraft debug start S03_01 client`

`/skycraft host 25565`

В PowerShell проверьте прямую цель:

`Test-NetConnection -ComputerName 127.0.0.1 -Port 25565`

Должно быть TcpTestSucceeded=True. Вернитесь в чат:

`/skycraft netcheck 127.0.0.1:25565`

Ожидается отказ подключения через SOCKS5 к 127.0.0.1:25566. Проверьте ввод/HUD, запишите текст, затем R2. Мастер: S03_01, Client, Loopback, игровой адрес 127.0.0.1, игровой порт 25565; режим SOCKS5 и отсутствующий прокси 25566 — в Notes.

**Что проверить:**

Прямая игровая цель доступна, но выбранный прокси отсутствует. Успешный netcheck здесь — FAIL: он не должен обходить выбранный транспорт. Если не получилось открыть 25565, этот критерий не проверен: PARTIAL, сначала разберите порт. Наблюдайте не менее 3 минут с начала проверки.

### B8 — S03_02: повторить для HTTP CONNECT

**Что сделать:**

После сбора S03_01 закройте обе игры по G2. В MINECRAFT\config\skycraft.properties замените только строку режима на:

`network.mode=HTTP_CONNECT`

Остальные тестовые строки B6 оставьте. Сохраните по G4, запустите по G5. Повторите B7, используя команды:

`/skycraft debug start S03_02 client`

`/skycraft host 25565`

`/skycraft netcheck 127.0.0.1:25565`

Перед netcheck снова подтвердите прямой TCP PowerShell-командой B7. После 3 минут и R2 соберите отчёт: S03_02, Client, Loopback, 127.0.0.1, 25565; HTTP_CONNECT в Notes.

**Что проверить:**

Прямая цель доступна; отказ происходит на отсутствующем HTTP-прокси 25566. Два режима имеют два отдельных ZIP. Ожидаемый отказ — PASS, неожиданный обход — FAIL. /join в открытый на себе 25565 не выполняйте.

### B9 — Вернуть DIRECT и проверить восстановление

**Что сделать:**

1. Закройте обе игры по G2. В файле MINECRAFT\config\skycraft.properties примените пять базовых строк G4; proxy/username/password можете вернуть из копии G3, при DIRECT они не используются. Сохраните и выполните G5.

2. Повторите B1–B3 с новым ID S01_02 вместо S01_01 во всех командах и мастере.

3. Убедитесь, что netcheck снова успешен и HUD работает.

4. Верните исходные состояния сетевых программ. Если требуется полностью прежняя конфигурация — G8.

**Что проверить:**

Сохраните отдельный ZIP S01_02-host. Он подтверждает, что после отрицательных тестов базовый режим восстановился.

### B10 — Что передать после проверки одному

**Что сделать:**

Из reports распакованного комплекта: installation-*.zip проверки сборки; S01_01-host-*.zip; S02_01-client-*.zip; S03_01-client-*.zip; S03_02-client-*.zip; S01_02-host-*.zip. Имена могут включать UTC и дополнительные символы; выбирайте по ID и роли. Добавьте рабочую копию XLSX или текст с результатами каждого теста. Если HUD/чат не работали, вместо невыполненных тестов пришлите STARTUP-client-*.zip по R1 и напишите, где остановились.

**Что проверить:**

Эти тесты проверяют запуск, логгер, локальный TCP, обработку ошибок и восстановление. Внешняя доступность, NAT/CGNAT, вход другого игрока и совместное движение/блоки остаются NOT_RUN. Включение VPN для повторного loopback-теста проверит только этот локальный путь.

### B11 — Необязательный автоматический тест разработчика S04

**Что сделать:**

В friend-kit исходников нет — там S04 оставьте NOT_RUN. На ПК с уже настроенными исходниками откройте PowerShell в папке source: в Проводнике откройте source, в адресной строке наберите powershell и Enter. Затем:

`powershell -NoProfile -ExecutionPolicy Bypass -File tools/dev.ps1 -Action NetworkSmoke`

Тест запускает отдельный Minecraft с локальным тестовым HTTP-прокси и закрывается сам. Пока он идёт, не запускайте новые ручные проверки.

**Что проверить:**

Результат: source\.tools\network-smoke-game\network-smoke-result.txt. Откройте в Блокноте, ожидается PASS. Этот тест проверяет настоящий пакет входа и HTTP CONNECT; второго игрового мира и другого игрока в нём нет.

## Сбор отчётов: каждое поле

### R1 — Если не запускается игра, HUD или чат

**Что сделать:**

1. До нового запуска откройте папку распакованного комплекта и двойным щелчком запустите «Собрать отчёт.cmd».

2. На «Режим [1]» введите 1 и Enter.

3. На «Каталог Minecraft» вставьте полный путь из G1. Enter без ввода допустим только если показанный путь точно тот же.

4. В описании укажите этап: Bethesda/меню/загрузка/HUD/чат, точное сообщение и время.

5. На «Добавить latest.log, SkyCraft.log и логи SKSE?» ответьте no для обычного отчёта или yes, если нужны полные логи. При yes просмотрите их до передачи.

**Что проверить:**

Сборщик напечатает полный путь к созданному ZIP. Это STARTUP-client-…zip в папке reports внутри комплекта. Здесь собирается последний AUTO-лог запуска, если он есть. Автоматической отправки нет.

### R2 — Как закончить размеченный тест

**Что сделать:**

В чате игры по одной команде:

`/skycraft debug mark RUN_END`

`/skycraft debug stop`

Подождите 2 секунды. Затем Alt+Tab и «Собрать отчёт.cmd» из распакованного комплекта → режим 2. Если игра аварийно закрылась, сразу собирайте отчёт с прежним ID, не запускайте игру ещё раз до сбора.

**Что проверить:**

RUN_END — буквальная метка, заменять её не надо. ID указывается при debug start и в мастере сборщика. Если игра упала, отсутствие события trace_closed допустимо как факт сбоя, но запись отмечается незавершённой.

### R3 — Первые поля сетевого мастера

**Что сделать:**

«Каталог Minecraft (с папкой mods)»: путь из G1.

«Тот же ID, что в debug start»: ровно введённый ID, например S01_01.

«Роль этого ПК»: Host, если лог был запущен с host; Client, если с client.

«Где соединяются игроки»: Loopback для одного ПК и 127.0.0.1; LAN для одной домашней сети; Internet для разных сетей.

«IP или DNS-имя хоста без порта»: только адрес, например 127.0.0.1. Для IPv6 без [] и без порта.

«Порт игрового хоста»: отдельное число, например 25565.

**Что проверить:**

Все значения вводятся отдельными ответами и подтверждаются Enter. В S03 поле цели — игровой адрес 127.0.0.1 и порт 25565; недоступный прокси 127.0.0.1:25566 описывают в Notes. Это разные адреса.

### R4 — Режимы и итог в мастере

**Что сделать:**

«zapret во время прогона»: off/on/unknown.

«Cloudflare»: off/dns/traffic_dns/unknown.

«VPN»: off/tunnel/system_proxy/unknown. Указывайте состояние ЭТОГО ПК в момент теста.

«Итог»: pass/fail/blocked/not_run/partial, строчными буквами, как в подсказке. Для ожидаемого отказа S02/S03 pass означает правильную обработку отказа.

«Что произошло»: режим SkyCraft (DIRECT/SOCKS5/HTTP_CONNECT), сообщения, время, наблюдения. Пароли, токены и ссылки подписки не пишите.

**Что проверить:**

Enter оставляет значение в квадратных скобках; не принимайте unknown/partial молча, если знаете результат. В таблице те же статусы написаны заглавными PASS/FAIL/BLOCKED/PARTIAL/NOT_RUN. Режим network.mode запишите в «Условия прогонов → Транспорт клиента».

### R5 — Где лежит отчёт и как его прочитать

**Что сделать:**

1. Скопируйте полный путь ZIP из последней строки мастера. Либо откройте reports внутри распакованного комплекта, отсортируйте по времени изменения и найдите имя с нужным ID и ролью.

2. Для чтения: ПКМ по ZIP → «Извлечь всё» в отдельную папку. Откройте summary.json через «Открыть с помощью → Блокнот». Для events.csv в Excel: Данные → Из текста/CSV → выбрать файл → кодировка UTF-8 → разделитель точка с запятой → Загрузить. Исходный JSONL лежит в подпапке traces.

3. В summary.json ищите TraceFiles, Events, TraceStopped, DroppedTraceEvents. TraceFiles > 0 и Events > 0 означают, что найден лог; TraceStopped=true — присутствует завершение.

4. В events.csv включите Данные → Фильтр и отфильтруйте столбец event: host_open, probe_result, world_join, return_to_own_world, trace_closed.

**Что проверить:**

Для успешного netcheck событие probe_result имеет result=tcp_ready; для ожидаемого отказа — failed. Пустое поле/null означает отсутствие измерения, а не ноль. Для исходных логов: MINECRAFT\logs\skycraft-network; точный файл показывает /skycraft debug status. Отправляйте исходный ZIP отчёта, не заново упакованную папку.

### R6 — Как заполнить таблицу

**Что сделать:**

Откройте SkyCraft-Network-Tests.xlsx из docs\testing комплекта и сохраните свою рабочую копию.

«Прогоны»: найдите Run ID, заполните итог, TCP, длительность в минутах и имя ZIP. Движение/блоки обоим и leave/rejoin для одного ПК — NOT_RUN, поля входа/пинга оставьте пустыми. Для двух ПК нужны наблюдения обеих сторон.

«Условия прогонов»: та же строка ID; начало UTC из первого события environment, адрес:порт, источник адреса, версии, состояния программ для каждой участвующей стороны. Для одного ПК в поле второй стороны напишите «второго ПК нет».

**Что проверить:**

S01_01: роль Host, Loopback, 127.0.0.1, порт 25565. S02_01: Client, Loopback, 127.0.0.1, порт 25566. S03_01/S03_02: Client, Loopback, 127.0.0.1, порт 25565. Во всех случаях впишите фактические состояния программ; для базовой проверки это off/off/off.

Если нужно больше трёх попыток: в Excel перейдите в последнюю ячейку последней строки таблицы «Прогоны» и нажмите Tab — добавится строка. Укажите сценарий, новый ID и NOT_RUN; результаты заполните после теста. Так же добавьте строку того же ID в «Условия прогонов».

## Как оценить результат

PASS — все ожидания именно этого сценария выполнены. FAIL — ожидание нарушено. BLOCKED — нет необходимых условий. PARTIAL — проверена только часть или условие среды не подтверждено. NOT_RUN — не запускали. Для S02/S03 ожидаемая ошибка может дать PASS.

Для одного ПК передайте отчёты B10; для двух ПК — ZIP хоста и клиента с одним ID и рабочую XLSX. Конфиг, аккаунты и резервные копии мира не отправляйте. Сборщик ничего сам не отправляет.
