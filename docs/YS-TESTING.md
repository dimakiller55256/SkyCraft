# Тестирование сети SkyCraft YS

Набор для **0.1.2-ys.network.2**: [таблица Excel](testing/SkyCraft-Network-Tests.xlsx),
[матрица CSV](testing/scenarios.csv), [журнал CSV](testing/runs-template.csv),
[сборщик Windows](../tools/collect-network-report.cmd). Таблица содержит вкладки
«Начать», «Шаги», «Матрица», «Прогоны», «Откуда данные» и «Разбор сбоя».
В матрице 25 сценариев; игровые результаты изначально не заполнены.

Сейчас, пока есть один ПК, начните с **S01–S03**. Они проверят команды, порт,
логгер и обработку отказов. **Не делайте `/join` в собственный открытый мир из
того же экземпляра**: эта команда сначала закрывает свой мир. Совместную игру
проверяем с другом, начиная с **L01** в одной LAN либо **I01** в разных сетях.
Разработческий S04 уже прошёл: настоящий клиент Minecraft отправил пакет входа
через локальную тестовую HTTP-прокси. Это не проверка двух игроков или Skyrim.

## Подготовка один раз

1. Закройте Minecraft и Skyrim. В Prism скопируйте экземпляр SkyCraft для тестов;
   используйте отдельное сохранение Skyrim и тестовый мир Minecraft.
2. Откройте каталог Minecraft этой копии через Prism. В вашей существующей
   установке это `D:\PrismLauncher\instances\SkyCraft\minecraft`; у копии путь
   изменится. Правильная папка содержит `mods`, `config`, `logs`.
3. Сохраните старый SkyCraft JAR вне `mods`. Поместите новый
   `skycraft-fabric-0.1.2-ys.network.2.jar` в `mods`. В `mods` должен остаться ровно
   один SkyCraft JAR. Старый e4mc JAR также перенесите вне `mods`. Fabric API оставьте.
   Этот JAR устанавливается в Minecraft; MO2 обслуживает SKSE-часть.
4. Используйте Minecraft **26.3**, Fabric Loader **0.19.5**, Fabric API
   **0.161.0+26.3**. Shared-memory протокол прежний, SKSE-плагин 0.1.2 подходит по
   формату; его работу вместе с этой сборкой ещё предстоит проверить в игре.
5. В `config/skycraft.properties` сохраните остальные настройки. Начальная сеть:

   ```properties
   join=
   network.mode=DIRECT
   network.proxy=127.0.0.1:1080
   network.proxy.username=
   network.proxy.password=
   network.timeoutMillis=10000
   network.hostPort=25565
   network.advertisedAddress=
   ```

   При DIRECT поля прокси не используются. `join=` пустой, чтобы начать в своём
   мире. Настройки перечитываются при `/join`, `/skycraft host`, `netcheck`.
6. Запускайте SkyCraft своим обычным способом через MO2/Prism. Откройте чат
   Minecraft клавишей **T**. Проверьте `/skycraft debug status`: путь к JSONL
   должен отображаться. Если игра скрывает окно/чат, используйте предусмотренное
   вашим запуском переключение в Minecraft; для отдельного запуска есть JVM-флаг
   `-Dskycraft.showWindow=true`. Запишите, удалось ли увидеть команды в игре.

## Что означают адреса и режимы

| Данные | Откуда взять | Как использовать |
|---|---|---|
| Каталог Minecraft | Prism → экземпляр → папка Minecraft | Путь к `mods/config/logs`, передаётся сборщику |
| LAN IP хоста | На хосте PowerShell-команда ниже или `ip-addresses.json` в отчёте | Адрес активного адаптера, через который оба ПК находятся в одной LAN; например `192.168.1.20:25565` |
| Адрес для другого ПК | Хост передаёт клиенту адрес и порт | `127.0.0.1` всегда означает текущий ПК и для друга не подходит |
| Внешний IP/DNS | WAN-адрес/настройки роутера, сведения провайдера, собственная DNS-запись | Требуется доступный входящий TCP-порт. Адрес за CGNAT сам по себе вход не открывает |
| IPv6 | Глобальный адрес хоста и рабочий IPv6-маршрут клиента | `/join [действительный-IPv6]:25565`; `fe80::` для Интернета не подходит |
| Порт хоста | Сообщение `/skycraft host 25565`, событие `host_open` | Если внешний порт отличается, клиент использует внешний порт |
| Прокси | Настройки VPN-программы: SOCKS/HTTP/mixed порт | В `network.proxy` вписывается реальный `IP:порт`; 1080 здесь лишь пример |
| Режимы zapret/WARP/VPN | Интерфейс/профиль каждой программы | Записать версию, профиль, DNS-протокол, порядок включения; процесс в памяти этого не доказывает |
| Версия/хеш JAR | `mod-versions.json`, `environment` в JSONL | На обоих ПК должна быть одна тестовая сборка |

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
    Select-Object InterfaceAlias, IPAddress, AddressState
```

Для начального LAN-теста выберите IP физического Ethernet/Wi-Fi адаптера вашей
общей сети. Адреса `127.*` и `169.254.*` не передавайте другу для этого теста.
Сеть гостевого Wi-Fi может изолировать клиентов; такой случай фиксируйте отдельно.

**DIRECT** использует обычное подключение Minecraft и маршруты Windows. VPN в
режиме туннеля проверяется с DIRECT. Системный прокси Windows автоматически не
импортируется: для VPN в режиме прокси выберите **SOCKS5** либо **HTTP_CONNECT**
и явно впишите соответствующий порт программы в конфиг клиента. Например:

```properties
network.mode=SOCKS5
network.proxy=127.0.0.1:1080
```

Для HTTP/mixed порта — `network.mode=HTTP_CONNECT`. Имя игрового хоста разрешает
прокси; имя самого прокси разрешается на ПК клиента. Укажите игровой порт явно:
поиск Minecraft SRV через прокси не реализован. Через удалённый VPN-прокси LAN
адрес друга может быть недоступен. Прокси клиента также не делает входящий порт
хоста доступным. Ретранслятор для двух игроков за закрытым NAT пока не реализован.

## Один прогон: хост и клиент

Выберите строку матрицы. Договоритесь об одном **Run ID**: например `L01_01`
(сценарий L01, попытка 01). Только латинские буквы, цифры, `_` и `-`, до 64
символов. При изменении режима, адреса, профиля или ролей используйте новый ID.
В строке «Прогоны» заполните условия **обоих** ПК и время начала UTC.

Все команды ниже вводятся в чате Minecraft. Замените `192.168.1.20:25565`
реальным адресом хоста, доступным клиенту.

| Шаг | Хост | Клиент | Что фиксировать |
|---|---|---|---|
| 1. Свой мир | `/skycraft debug start L01_01 host` | `/skycraft debug start L01_01 client` | Одинаковый ID, разные роли; status показывает путь без ошибки записи |
| 2. Открыть сервер | `/skycraft host 25565`, затем `/skycraft debug mark HOST_READY`; передать адрес | Дождаться HOST_READY | Порт, адрес, точное время; сообщение об открытии |
| 3. Проверить транспорт | Держать мир открытым | `/skycraft netcheck 192.168.1.20:25565` | Результат/текст отказа; успех TCP ещё не означает игровой вход |
| 4. Войти | Дождаться второго игрока | `/join 192.168.1.20:25565` | Время входа из `world_join`; какой мир виден после команды |
| 5. Проверить картинку | Увидев клиента: `/skycraft debug mark PEER_SEEN`; пройти 10 блоков | `/skycraft debug mark JOIN_SEEN`; увидеть движение хоста и пройти 10 блоков | Обоим видно движение? Если есть задержка, записать наблюдение |
| 6. Блоки в обе стороны | Поставить и сломать 3 обычных Minecraft-блока; дождаться изменений клиента | Увидеть блоки хоста; поставить и сломать свои 3 блока | Если оба увидели изменения: каждый `/skycraft debug mark BLOCK_BOTH_OK`. При сбое — `BLOCK_FAIL` и описание |
| 7. Стабильность | Оставаться в мире, двигаться/строить | Играть указанное в матрице время; смотреть на зависания/откаты | Фактическая длительность и число неожиданных разрывов; ping автоматически раз в 5 с |
| 8. Повторный вход | Оставаться хостом | `/skycraft debug mark LEAVE_BEGIN`, `/leave`; в своём мире `/skycraft debug mark OWN_WORLD_OK`; затем снова `/join ...` | Возврат в свой мир, повторный вход, сохранился ли поставленный блок у хоста |
| 9. Завершить | `/skycraft debug mark RUN_END`, `/skycraft debug stop` | Такие же две команды | Подождать 2 с; до ухода хоста сохранить наблюдения обоих |
| 10. Собрать отчёт | Запустить CMD-сборщик, роль Host | Запустить CMD-сборщик, роль Client | Два ZIP с одним ID, строка таблицы и итог |

Если вход провалился, не надо выполнять оставшиеся игровые шаги: после возврата
в свой мир поставьте `JOIN_FAIL`, запишите точное сообщение, выполните `debug stop`
и соберите отчёт. Если клиент упал, сборщик всё равно запускается; отсутствие
`trace_closed` означает незавершённый лог. При перезапуске игры и продолжении того
же прогона снова выполните `debug start` с тем же ID и ролью: сборщик включит оба
файла. Для новой попытки используйте новый ID.

В S01–S03 один ПК может иметь роль `client` для проверки команды `netcheck`.
Это роль в отчёте, второго игрока она не создаёт. Не ставьте PASS совместной игре
только по этим сценариям. Для S02/S03 ожидаемый отказ считается PASS обработки
ошибки; сначала убедитесь, что тестовый порт действительно свободен:

```powershell
Get-NetTCPConnection -State Listen -LocalPort 25566 -ErrorAction SilentlyContinue
```

## Собрать ZIP без ручного поиска логов

Распакуйте набор тестирования в обычную папку. Дважды щёлкните
**`collect-network-report.cmd`**. Мастер спросит путь Minecraft, ID, роль,
адрес хоста, условия и результат. Его ID должен точно совпадать с `debug start`.
Обычно права администратора не нужны. Недоступные проверки Windows попадут в
`collection-errors.json`, а доступные данные сохранятся. Архив и папка с его
содержимым будут в **`reports` рядом с папкой `tools`**.

Пример вызова из корня `source` на клиенте (замените путь и адрес):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/collect-network-report.ps1 `
  -GameDirectory 'D:\PrismLauncher\instances\SkyCraft\minecraft' `
  -RunId L01_01 -Role Client -TargetHost 192.168.1.20 -TargetPort 25565 `
  -NetworkLabel LAN -ZapretState off -CloudflareState off -VpnState off `
  -Result pass -Notes 'Блоки в обе стороны видны; 5 минут, 0 обрывов'
```

На хосте меняется `-Role Host`. Для вашей полной комбинации:
`-ZapretState on -CloudflareState traffic_dns -VpnState tunnel` или
`system_proxy`. DNS UDP и точные профили допишите в `-Notes`/таблицу.

Для наблюдения TCP во время игры запустите сборщик с `-WatchSeconds 180` **после
debug start и до /join**. Он снимает соединения примерно раз в 5 с, игру можно
продолжать. Эта промежуточная копия лога может быть незавершённой. После
`debug stop` соберите окончательный ZIP с `WatchSeconds=0`; при необходимости
сохраните обе копии. Начальный снимок адаптеров/маршрутов относится ко времени
старта сборщика. После переключения VPN сделайте ещё один снимок и укажите Notes.

## Что в отчёте и куда это перенести

| Файл | Данные | Поле таблицы / смысл |
|---|---|---|
| `run.json` | UTC, часовой пояс, роль, ID, вручную указанные режимы/результат | Время и условия прогона; unknown означает, что режим не указан |
| `skycraft-settings.json` | Выбранный транспорт, адрес прокси, наличие учётных данных, таймаут | Транспорт и прокси; пароль/имя пользователя исключены |
| `mod-versions.json` | Имена/хеши JAR, версии компонентов Prism при наличии | Установленная сборка |
| `summary.json` | Вход в удалённый мир в мс, средний/максимальный ping, полнота лога | Поля «Вход, мс», «Ping сред./макс.»; без данных оставьте пустыми |
| `events.csv` | UTC, этап, ID попытки, исключение, HTTP/SOCKS-код, метки | Последний успешный этап и первая ошибка |
| `traces/*.jsonl*` | Исходные события и ротации | Для разбора разработчиком |
| `tcp-samples.csv` | TCP-сокеты выбранного игрового/прокси порта, PID и процесс | LISTEN/ESTABLISHED и фактические адреса; при WatchSeconds=0 один снимок |
| `adapters`, `ip-addresses`, `interfaces`, `dns-servers`, `default-routes` JSON | Состояние сетевой среды | Какой адаптер/маршрут использовался, DNS; полного дампа маршрутов нет |
| `target-route.json` / `target-dns.json` | Выбранный маршрут к IP либо локальный DNS-запрос | Локальный DNS-отказ не доказывает отказ удалённого DNS через прокси |
| `system-proxy.json`, `process-presence-hints.json` | Адрес системного прокси без секретов, наличие процессов | Подсказка; фактический режим подтверждает тестировщик |
| `collection-errors.json`, `warnings.json` | Недоступные разделы, отсутствие/неполнота лога | Прикладываются к любому результату, сбор не выдаёт автоматический PASS |

Ping берётся из значения задержки Minecraft для текущего игрока, которое сам
сервер обновляет со своей частотой; запись раз в 5 с не создаёт новое измерение
RTT. Первые нули возможны до обновления. Время `netcheck` — длительность
установления TCP/прокси, **не ping**. Байтовые счётчики есть только у прокси-моста;
это объём потока, включая служебный трафик. Прямое соединение не имеет таких
счётчиков. Логгер не рассчитывает потери пакетов и не определяет CGNAT автоматически.

JSONL пишется автоматически с запуска; команды debug создают отдельный лог
конкретного прогона. Один файл до 4 МиБ плюс три ротации, очередь до 512 событий.
Счётчик `dropped_events` в конце показывает пропуски при переполнении очереди.
Старые сессии автоматически не удаляются; после диагностики их можно убрать
вручную. Для отключения автологгера JVM-флаг `-Dskycraft.networkTrace=false`;
команда debug start всё равно позволяет включить его вручную.

В сборке собираются технические метаданные, IP/имена узлов и адаптеров, версии и
ваши метки. Пароли прокси, токены, файлы аккаунтов, исходный конфиг, содержимое
игровых пакетов и чат автоматически не копируются. Не вводите секреты в метки и
Notes. Отчёт хранится локально; программа никуда его не загружает. По указанному
DNS-имени возможен обычный DNS-запрос. Полные `latest.log` и SKSE-лог включаются
только флагом `-IncludeGameLogs`; они могут содержать имена, чат и дополнительные
пути. Пользовательский SKSE-лог можно передать через `-SkseLog 'путь'`.

## Как оценить результат

- **PASS**: выполнены все ожидаемые шаги именно выбранного сценария. Для
  совместной игры оба видели движение/блоки, выдержано время, повторный вход
  работал. Для намеренного отказа PASS означает корректную обработку отказа.
- **FAIL**: условия сценария выполнены, но ожидание нарушилось. Приложить этап,
  сообщение, UTC, два отчёта и воспроизводимые шаги.
- **BLOCKED**: отсутствует друг, доступный входящий порт, IPv6 или нужный прокси.
  Написать, какого условия не хватает; приложить доступную диагностику.
- **PARTIAL**: проверена только часть, например TCP без входа в мир.
- **NOT_RUN**: не запускалось либо нужное действие не произошло, например
  соединение закончилось до нажатия «Отмена».

Не переиспользуйте успешный результат между SOCKS5 и HTTP CONNECT или между
одиночным VPN и полной комбинацией инструментов. Повторите критичные L01/I01 и
N08/N09 три раза (`_01`, `_02`, `_03`). В «Прогоны» впишите фактическую длительность,
число обрывов, блоки/движение в обе стороны, путь к ZIP хоста и ZIP клиента.

Для разбора достаточно строки таблицы и двух ZIP. В комментарии напишите:

```text
Run ID: N08_01
Хост: версия сборки, сеть, zapret/WARP/VPN + версии/профили
Клиент: те же данные; transport DIRECT/SOCKS5/HTTP_CONNECT
Шаг сбоя: /join / блоки / повторный вход / переключение VPN
Ожидал: ...
Получил: точный текст сообщения, что было видно
Время UTC: ... (маркер в логе: ...)
Повторяемость: 2 из 3 попыток
ZIP хоста: ...; ZIP клиента: ...
```

## Разбор типичных сбоев

| Наблюдение | Где посмотреть | Следующий шаг |
|---|---|---|
| Команда неизвестна | Версия JAR, дубликаты в mods, Loader | Убедиться, что запущен тестовый экземпляр и версия network.2 |
| Нет JSONL / ошибка записи | debug status; warnings/collection-errors | Проверить путь, ID/роль, доступ на запись; stop и повторный сбор |
| UnknownHostException | dial_phase, target-dns, proxy_host | Проверить адрес; сравнить IP/имя. Через прокси отдельно проверить имя самого прокси |
| ConnectException / TCP refused | LISTEN на хосте, порт, адрес, proxy_host | Подтвердить открытый мир и достижимый порт; повторить netcheck |
| Таймаут | Последний dial_phase, оба ZIP | Разделить этап TCP и ответ прокси; проверить маршрут в выбранном режиме |
| HTTP 407 / отказ SOCKS auth | http_connect_result / socks_auth | Проверить локально учётные данные; секреты не включать в отчёт |
| HTTP 403 или другой код | http_connect_result | Уточнить, разрешает ли ваш прокси CONNECT к этому адресу/порту |
| TCP готов, вход не состоялся | world_join, channel_error, сообщение Minecraft | Сравнить версии модов/игры, причину игрового отказа; при необходимости полный latest.log |
| Вошли, блоки не совпали | BLOCK_FAIL и время; оба лога | Описать конкретный блок/действие, видимость у каждого; отдельно проверить движение |
| Разрыв после смены VPN | SWITCH_BEFORE/AFTER, маршруты до/после | Дождаться стабилизации и проверить ручной вход; непрерывность TCP не гарантируется |
| Нет входящего порта / оба за закрытым NAT | Адреса/условия провайдера и маршруты | BLOCKED; нужен доступный узел/будущий ретранслятор, текущая сборка его не предоставляет |

Эта приёмка касается Minecraft-сети SkyCraft. Синхронизация квестов/NPC Skyrim,
интеграция Skyrim Together Reborn и конвертация предметов ещё не реализованы;
их нельзя отмечать PASS по результатам этой таблицы. STR потребуется отдельная
проверка его UDP-транспорта.

## Воспроизведение разработческих проверок

```powershell
powershell -ExecutionPolicy Bypass -File tools/dev.ps1 -Action BuildFabric
powershell -ExecutionPolicy Bypass -File tools/dev.ps1 -Action NetworkSmoke
python tools/test-network-report.py
python tools/create-network-test-kit.py
```

Генератор таблицы требует openpyxl 3.1.5; в этой среде использует локальную копию
из `.tools/table-python`. Сценарии хранятся в `docs/testing/scenarios.json`.
Сборщик требует только Windows PowerShell 5.1+, без Python и аккаунтов.
