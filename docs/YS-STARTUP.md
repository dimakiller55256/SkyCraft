# Если Skyrim закрывается до меню

Для начала проверяем обычный Skyrim через `SkyrimSELauncher.exe`, без MO2 и
SKSE, и только до главного меню. Если он тоже закрывается на заставке Bethesda,
сетевые настройки SkyCraft эту проверку не исправят: нужно исследовать базовый
запуск игры. Сохранения для такого теста не загружаются.

Anniversary Edition включает Special Edition и дополнительный контент Creation
Club; для SKSE-плагинов важны точный runtime и соответствующие зависимости.
Название редакции само по себе не устанавливает причину закрытия.
[Описание Bethesda](https://bethesda.net/en-US/news/skyrim-anniversary-edition-and-creation-club-content-first-look).

## Кэш сборки внутри каталога игры

В исследованном запуске Skyrim 1.7.104.0 обходил вложенные папки `Mods`,
включая отключённую в MO2 папку с исходниками. Закрытие происходило и без
MO2/SKSE. Минидамп показал `0xC0000409`, параметр fast-fail `5`
(`FAST_FAIL_INVALID_ARG`), в `ucrtbase!invoke_watson`.

В аргументах вызова `__stdio_common_vsprintf_s` восстановлены:

| Данные | Значение |
|---|---|
| Формат пути | `%s/%s` |
| Буфер | 260 байт |
| Путь к POM-файлу Fabric API в `.tools/gradle-user-home` | 260 ASCII-символов |
| Требуемый размер вместе с завершающим нулём | 261 байт |

Таким образом, служебный файл сборки не помещался в буфер игры. Microsoft
описывает аварийное завершение по `FAST_FAIL_INVALID_ARG` при стандартной
[обработке недопустимых аргументов CRT](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/invalid-parameter-functions?view=msvc-170).
Одна лишь надпись Anniversary Edition такого диагноза не даёт.

`tools/dev.ps1` теперь хранит Gradle-кэш вне Skyrim и отказывается собирать
Fabric, если указанный кэш находится под каталогом с `SkyrimSE.exe`.
Местоположение задаётся параметром `-GradleUserHome` или полем `gradleUserHome`
в `.tools/dev-local.json`; по умолчанию используется
`%LOCALAPPDATA%\SkyCraft\Gradle`.

Если уже есть старый кэш внутри игры, сначала остановите Gradle, затем
перенесите его за пределы каталога Skyrim и обновите локальную настройку.
Не создавайте на старом месте ссылку обратно на кэш. Исходники, зависимости
и каталоги сборки также лучше хранить вне папки игры: новые вложенные пути
могут снова превысить ограничение. Удалять сохранения или менять игровые DLL
для этой проверки не требуется.

После переноса проверяйте по порядку: обычный Skyrim до меню, SKSE/MO2 до
меню, затем SkyCraft на отдельном тестовом сохранении. Сам перенос ещё не
является подтверждением успешного запуска.
В текущей проверке после переноса пользователь подтвердил появление меню
обычного Skyrim; наблюдатель зафиксировал работающий процесс через 60 секунд.
Следующий ручной запуск через MO2/SKSE с включённым SkyCraft также дошёл до
меню. Логи подтвердили создание общей памяти, подключение Minecraft и
получение его текстур в Skyrim. Загрузка сохранения и игровой процесс в этой
проверке пока не выполнялись.

## Запись кода завершения

1. Закройте предыдущий Skyrim обычным способом, если он ещё работает.
2. Запустите `tools/capture-skyrim-startup.cmd` двойным щелчком.
3. В течение трёх минут запустите обычный Skyrim через его лаунчер.
4. Дождитесь закрытия игры либо появления меню. Скрипт наблюдает найденный
   процесс до двух минут, сам его не закрывает.
5. Откройте свежую папку `reports/skyrim-startup-*`; передайте `process.json` и,
   при наличии, `windows-events.json` для разбора.

Скрипт сохраняет UTC, PID, путь/версию EXE, статус наблюдения и код завершения
в десятичном и шестнадцатеричном виде. Это дополнительная улика, а не готовый
диагноз. Например, ненулевой код нужно сопоставлять с модулем/стеком и этапом
запуска. Код 0 тоже не доказывает, что меню работало: игра могла закрыться сама.

Статус `still_running` означает только, что процесс не завершился за время
наблюдения; `not_observed` — что нужный процесс не был обнаружен. Недоступные
сведения попадают в Errors. Через параметры можно увеличить ожидание:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/capture-skyrim-startup.ps1 `
  -WaitSeconds 300 -ObserveSeconds 180
```

Для повторного запуска, когда старый Skyrim ещё открыт, добавьте
`-WaitForNewProcess`: уже существующие PID будут пропущены. Закройте игру
через меню и запустите следующий проверяемый вариант.

Наблюдатель не запускает игры, не меняет INI/моды/реестр и ничего не загружает
в Интернет. Он копирует существующие `SkyCraft.log`, `skse64.log` и
`skse64_loader.log` для сравнения. Обычный запуск без SKSE эти файлы не обновляет;
их время нужно учитывать отдельно. Другие игры и процессы Minecraft не затрагиваются.

На 03.10.2026 наблюдатель проверен на локальном тестовом процессе: сохранён код
37 (`0x00000025`); при ручном запуске Skyrim он записал `0xC0000409`.
Это не является проверкой успешного запуска Skyrim.

## Метаданные минидампа

Сбор дампа требует отдельного согласия пользователя: в дампе могут находиться
фрагменты памяти процесса. Для текущего исследования разрешение на Microsoft
ProcDump и его лицензию получено; дамп сохраняется локально и не отправляется
в репозиторий. Не используйте `-k` или полную выгрузку памяти без необходимости.

Существующий дамп можно прочитать без дополнительных Python-библиотек:

```powershell
python tools/inspect-minidump.py C:\path\to\SkyrimSE.dmp --output exception.json
```

Утилита выводит код/параметры исключения, модуль, регистры AMD64 и пути
загруженных модулей. `stack_address_candidates` — адреса, найденные в сырых
данных стека; они могут быть данными, а не адресами возврата. Полноценную
раскрутку стека или окончательный диагноз этот список не заменяет.
