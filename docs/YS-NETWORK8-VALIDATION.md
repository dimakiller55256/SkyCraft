# network.8-r9 — удар великана и ожидание поверхности

В настоящем одиночном прогоне r8 залипание клавиш пока не повторилось. Уточнённый противник — великан. Его удар был ошибочно классифицирован как magic: 178,49 Skyrim damage превратились в 35,698 HP Minecraft, здоровье 20 → 0, причина смерти indirectMagic. Две последующие смерти были fall при обычном движении, отдельно от этого удара. Источник обоих провалов по прежней телеметрии до конца не установлен; утверждать, что это только задержка загрузки, нельзя.

## Исправления r9

Проверенный AE call site обработки ближней атаки теперь сохраняет её физический тип до применения удара в Skyrim. Он использует уже проверенные адрес и сигнатуру существующего моста ProcessHit; при несовпадении исходного вызова перехват не устанавливается. TESHitEvent принимается и во время передачи анимации Skyrim. Свежесть события измеряется монотонными часами: большой кадровый delta больше не делает только что полученный удар устаревшим. Один известный атакующий без сведений о типе больше не считается доказательством магии. Явные заклинания вне обработки ближнего удара остаются magic.

Minecraft сообщает новый флаг действительно поднятого щита. Для фронтального ближнего удара в таком состоянии Skyrim stagger/pushBack обнуляются до обработки. Сам урон передаётся в Minecraft для обычного решения щитом, бронёй и направлением. Это не отменяет неприкрытые удары, магию и атаки сзади. Независимая физика/скрипт великана всё ещё нуждаются в приёмке: один успешный C++ build не доказывает отсутствие любого ragdoll.

Новый флаг SKY_TAKEOVER замораживает Minecraft во время ragdoll, мебели и сцен Skyrim; ввод освобождается. Владение здоровьем и MC_IN_WORLD не отзываются только из-за передачи анимации. Изменение teleportSeq во время takeover откладывается до возврата управления, чтобы скрытый Minecraft не падал сам по себе и не выдавал промежуточное положение за новый спавн. Layout и версия shared memory сохранены; новые битовые флаги зеркально объявлены в C++ и Java. Обновить JAR и DLL вместе.

Перед физическим перемещением локального игрока проверяются все регионы swept box и пола: для каждого должны быть получены и треугольники, и voxel-ответ. При неполных данных движение удерживается, пока они приходят. Известное пустое пространство остаётся пустым: обычные обрывы и выкопанные отверстия не превращаются в невидимый пол. Новая поверхность terrain, появившаяся не выше 0,6 блока над неглубоко опустившимися ногами, может восстановить положение; потолки, объекты и большие падения для этого не используются.

Во время удержания, восстановления и падения logger записывает координаты, эпоху, известность регионов, distance падения, выкопанность клетки и ограниченный снимок близкой геометрии. В логах боя есть тип атаки, поднятый щит, броня, направление и здоровье до/после; в логах смерти — причина и положение. Помощник имеет отдельную оценку **Поверхность/провалы**. Файлы и координаты остаются в локальном отчёте, не в GitHub.

## Приёмка

Базовая Java-сборка и unit tests; нативная RelWithDebInfo и проверка AE-вызовов; standalone C++ проверки времени и направления щита; реальные два Minecraft-клиента со сценарием collider, щитом/бронёй, LAN/PLAY, повторным входом, разрушением и владением NPC; Windows EXE self-test; точный распространяемый ZIP с проверками установки/отката.

Окончательные фактические результаты и контрольные суммы находятся в локальном отчёте самопроверки. До результата нового игрового прогона r9 щит великана, ragdoll и поверхность в настоящем Skyrim остаются **не подтверждены**. С другом также повторить G02/G05. STR не интегрирован.

Первый короткий повтор без друга: **G09** (ходьба/бег там, где был провал), затем **G06** (поднятый щит, один удар великана на тестовом сохранении). Действия и кнопки: [YS-GAMEPLAY.md](YS-GAMEPLAY.md), в комплекте **ИГРОВЫЕ-ПРОВЕРКИ.html**.
