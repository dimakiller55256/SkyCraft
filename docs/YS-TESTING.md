# Тестирование SkyCraft: подробная инструкция

Сборка 0.1.2-ys.network.2: Minecraft 26.3, Fabric Loader 0.19.5, Fabric API 0.161.0+26.3, Java 25. Проверенный Skyrim runtime 1.7.104.0, SKSE 2.3.1. У владельца проверены запуск, HUD и движение; реальная игра двух пользователей и комбинации VPN ещё требуют проверки. Эти инструкции проверяют Minecraft-сеть SkyCraft; совместные квесты Skyrim Together и конвертация предметов пока не реализованы.

Все подписи HOST_LAN_IP, HOST_WAN_IP, ENDPOINT и RUN_ID заменяются вашими значениями. Их нельзя вставлять буквально. Команды /... вводятся в чате Minecraft через T в Skyrim; команды Windows — в PowerShell. Примеры IP не являются адресами ваших ПК.

Таблица: [SkyCraft-Network-Tests.xlsx](testing/SkyCraft-Network-Tests.xlsx). В «Сценарии подробно» отфильтруйте ID: там полный порядок конкретного сценария, включая команды с его Run ID.

## Подготовка обоих ПК

### P1 — Распаковать комплект

**Что сделать:** Оба: распакуйте весь ZIP в отдельную папку вне Skyrim, например D:\SkyCraftTest. Не запускайте CMD прямо из ZIP. Не передавайте другу source, .tools или свою папку Prism.

**Что проверить:** В папке есть НАЧАТЬ.txt, tools, docs, JAR и package-manifest.json.

### P2 — Обновить Java-мод

**Что сделать:** Оба: закройте Skyrim и Minecraft SkyCraft. Если исходный SkyCraft 0.1.2 уже работает, запустите «Установить обновление.cmd»; укажите каталог Minecraft через Prism: ПКМ на экземпляре → Папка Minecraft. Выбирается папка с mods/config/logs, а не папка лаунчера. Старые SkyCraft/e4mc уйдут в SkyCraft-YS-backups рядом с экземпляром. Настройки и миры сохраняются.

**Что проверить:** Один SkyCraft 0.1.2-ys.network.2 JAR; активного e4mc нет. Fabric API остаётся. На обоих ПК один SHA256.

### P3 — Проверить версии

**Что сделать:** Оба: «Проверить сборку.cmd»: каталог Minecraft, затем каталог с SkyrimSE.exe. В Prism → Версии сверить Minecraft 26.3, Loader 0.19.5, Fabric API 0.161.0+26.3; в настройках Java — Java 25. Skyrim runtime 1.7.104.0, SKSE 2.3.1, Address Library для этого runtime. В MO2 включить исходный SkyCraft 0.1.2 и Address Library.

**Что проверить:** installation-*.zip не содержит необъяснённых FAIL. WARN требует ручной проверки, а не автоматического PASS.

### P4 — Проверить одиночный запуск

**Что сделать:** Оба: запустите SKSE через MO2, дождитесь меню, загрузите отдельное тестовое сохранение после Хелгена. Проверьте HUD Minecraft, движение WASD, камеру. Основное сохранение не перезаписывайте. Для сетевых тестов согласуйте одну и ту же локацию Skyrim и совместимый набор модов мира.

**Что проверить:** Оба отдельно видят HUD и управляют игроком. Без этого сначала отчёт запуска через «Собрать отчёт.cmd», режим 1. STR/совместные квесты пока не проверяются.

### P5 — Найти чат

**Что сделать:** На загруженном сохранении нажмите T в окне Skyrim: исходный SkyCraft передаёт чат Minecraft и текстовый ввод через свой мост. Наберите /skycraft debug status и Enter. Escape закрывает чат. Набирайте команды латиницей; переключите раскладку на английскую. Отдельное окно Minecraft не требуется.

**Что проверить:** В чате ответ SkyCraft, а не «Unknown command». Если T не открыл чат, запишите это как отдельный сбой ввода; не продолжайте команды вслепую.

### P6 — Создать исходные условия

**Что сделать:** Закройте оба SkyCraft. На обоих для первого успешного соединения оставьте network.mode=DIRECT, join= пустым. VPN/Cloudflare/zapret выключите через их интерфейсы только на время базового теста; запишите исходные состояния, чтобы вернуть их. Сетевые расширения тестируем по одному после успешного L01/I01.

**Что проверить:** Понятен базовый маршрут; режимы обоих ПК записаны. Если отключение невозможно, укажите реальные условия и PARTIAL вместо приписывания чистому тесту.

### P7 — Назначить роли и ID

**Что сделать:** Договоритесь: один ПК — host (владелец мира Minecraft), другой — client. Для LAN первый Run ID L01_01, для разных сетей I01_01. В новой попытке увеличьте номер: I01_02. На обоих один ID; роли разные. Откройте «Условия прогонов» и заполните строку ID, затем «Прогоны».

**Что проверить:** ID без пробелов/кириллицы, до 64 символов: буквы A–Z/a–z, цифры, _ и -. Пример ID вводится одинаково на обоих ПК.

## Как получить адрес хоста

### A0 — Выбрать ветку

**Точные действия:** Если оба ПК подключены к одному домашнему роутеру обычным Ethernet/Wi-Fi — A1–A3 (LAN). Если в разных квартирах/сетях — A4–A7 (Интернет IPv4) либо A8–A9 (IPv6). Доступ к одному VPN-провайдеру не делает ПК общей LAN. 127.0.0.1 — только текущий ПК.

**Результат / ограничения:** Назначьте переменные на бумаге: HOST_LAN_IP, HOST_ROUTER, HOST_WAN_IP, HOST_PORT=25565, EXTERNAL_PORT=25565, ENDPOINT. Это подписи, не текст для вставки в команду.

### A1 — Найти LAN IPv4 хоста

**Точные действия:** На хосте, не на клиенте: «Адреса хоста.cmd» либо PowerShell: Get-NetIPConfiguration. Найдите подключённый Ethernet/Wi-Fi, к которому относятся оба ПК. Запишите IPv4Address и IPv4DefaultGateway.NextHop. Не выбирайте loopback, 169.254.*, WARP/VPN/виртуальный адаптер вместо вашей физической LAN.

**Результат / ограничения:** HOST_LAN_IP = IPv4Address физического адаптера. HOST_ROUTER = его IPv4DefaultGateway.NextHop. Например 192.168.1.20 и 192.168.1.1; это примеры, берите свои значения.

### A2 — Передать LAN адрес

**Точные действия:** После /skycraft host 25565 хост передаёт другу HOST_LAN_IP:25565 текстом. Если IPv4 хоста реально 192.168.1.20, готовая строка 192.168.1.20:25565. Клиент использует адрес ХОСТА, не свой IPv4 и не шлюз роутера.

**Результат / ограничения:** ENDPOINT = HOST_LAN_IP:HOST_PORT. Для LAN проброс порта на роутере не нужен. Гостевой Wi-Fi с изоляцией клиентов может запретить соединение.

### A3 — Проверить LAN порт

**Точные действия:** После открытия мира клиент в PowerShell: Test-NetConnection -ComputerName HOST_LAN_IP -Port 25565 -InformationLevel Detailed. Подставьте свой адрес без :порт в ComputerName. Например: Test-NetConnection -ComputerName 192.168.1.20 -Port 25565. Смотрите TcpTestSucceeded, RemoteAddress, InterfaceAlias. Затем проверьте тот же адрес через /skycraft netcheck ENDPOINT в чате игры.

**Результат / ограничения:** True/успех netcheck = TCP открыт. False: проверить, что хост не вышел из мира, порт 25565 слушается, выбрана правильная LAN, нет гостевой изоляции и разрешён входящий TCP. PingSucceeded отдельно успех не доказывает.

### A4 — Найти WAN IPv4 в другой сети

**Точные действия:** Хост сначала получает HOST_LAN_IP и HOST_ROUTER по A1. Откройте в браузере http://HOST_ROUTER (или HTTPS/адрес из руководства роутера). Войдите своим паролем локально, в чат его не передавайте. На странице Internet/WAN/Статус найдите IPv4 именно WAN-подключения к провайдеру; запишите HOST_WAN_IP. Не берите адрес самого роутера 192.168.* и не копируйте выходной IP включённого VPN с сайта «мой IP».

**Результат / ограничения:** Если WAN — 10.*, 192.168.*, 172.16.*–172.31.* или 100.64.*–100.127.*, перед роутером ещё NAT. 100.64.0.0/10 выделен для общего адресного пространства провайдера. Один проброс на вашем роутере не обеспечивает внешний вход.

### A5 — Проверить NAT и выбрать хоста

**Точные действия:** Если WAN частный: выясните, чей вышестоящий роутер. Для двух собственных роутеров TCP-порт надо направить на каждом; при CGNAT провайдера нужен доступный публичный адрес от провайдера либо глобальный IPv6. Если публичный вход есть только у друга, поменяйте host/client. Если нет у обоих — I01=BLOCKED; сохраняйте факт, не ставьте FAIL моду.

**Результат / ограничения:** Собственного ретранслятора/автоматического NAT traversal в этой сборке ещё нет. Клиентский SOCKS/HTTP-прокси не открывает входящий порт хоста. Отсутствие публичного входа конфигом не исправляется.

### A6 — Направить TCP-порт на ПК хоста

**Точные действия:** Только для своего роутера: закрепите HOST_LAN_IP за MAC хоста (DHCP reservation), затем в Port forwarding/Virtual server создайте правило: TCP, внешний EXTERNAL_PORT=25565, внутренний IP=HOST_LAN_IP, внутренний порт HOST_PORT=25565. В Windows хоста разрешите входящий TCP 25565; подробные шаги F1 ниже. Запустите SkyCraft и /skycraft host 25565. Брандмауэр целиком не отключайте.

**Результат / ограничения:** Хост передаёт другу HOST_WAN_IP:EXTERNAL_PORT. Например внешний порт 30000 при внутреннем 25565 означает /join WAN_IP:30000; /skycraft host остаётся 25565. Пароль роутера не входит в адрес.

### A7 — Проверить Интернет с клиента

**Точные действия:** Клиент из другой сети: Test-NetConnection -ComputerName HOST_WAN_IP -Port EXTERNAL_PORT -InformationLevel Detailed. Затем /skycraft netcheck ENDPOINT выбранным игровым транспортом. Проверка своего WAN адреса с ПК хоста зависит от NAT loopback и не заменяет проверку друга. При VPN на хосте входящая доступность и обратный маршрут могут измениться — H01/H02 проверяют это заново.

**Результат / ограничения:** ENDPOINT = WAN IPv4 хоста + внешний порт. True/TCP успех — можно идти к /join. Если timeout: WAN/NAT, проброс, Windows firewall, правила роутера, VPN хоста и фильтрация.

### A8 — Найти глобальный IPv6

**Точные действия:** На хосте: Get-NetIPAddress -AddressFamily IPv6 | Select-Object InterfaceAlias,IPAddress,AddressState. Нужен Preferred глобальный адрес подключённого адаптера с реальным IPv6 от провайдера. Не передавайте ::1, fe80:: (link-local), fc*/fd* (локальные ULA), 2001:db8:: (пример документации). Если выбор непонятен, пришлите результат и не угадывайте.

**Результат / ограничения:** IPv6 ENDPOINT = [IPv6_ХОСТА]:25565, со скобками. В PowerShell ComputerName адрес без скобок и без :порт. Нужен рабочий IPv6 на обоих ПК.

### A9 — Проверить IPv6 снаружи

**Точные действия:** Откройте мир на хосте. Для IPv6 обычно не нужна трансляция IPv4-порта; в IPv6 firewall роутера и Windows хоста разрешите входящий TCP 25565 к выбранному IPv6. Клиент: Test-NetConnection -ComputerName IPv6_ХОСТА -Port 25565. Затем /skycraft netcheck [IPv6_ХОСТА]:25565 и /join [IPv6_ХОСТА]:25565. После смены адреса IPv6 получите его заново.

**Результат / ограничения:** Успех TCP с клиента подтверждает доступ к порту. IPv6 от VPN не считать доступным входящим адресом без этой проверки.

### F1 — Правило Windows firewall

**Точные действия:** На хосте Win+R → wf.msc → Правила для входящих подключений → Создать правило → Для порта → TCP → Определённые локальные порты: 25565 → Разрешить подключение → профиль вашей текущей сети (обычно Частный; при текущем Общедоступном нужен именно он) → имя SkyCraft TCP 25565. Для профиля сети: Get-NetConnectionProfile. Если Java уже разрешена и TCP проходит, нового правила не требуется.

**Результат / ограничения:** Правило открывает именно входящий игровой порт. Профиль «только Частный» не сработает, если активная сеть Windows «Общедоступная». После теста ненужное созданное правило можно удалить по этому имени.

### F2 — Порт слушается на хосте

**Точные действия:** После /skycraft host 25565 на хосте: Get-NetTCPConnection -State Listen -LocalPort 25565 | Select-Object LocalAddress,LocalPort,OwningProcess. Если пусто — сервер не открылся/закрыт или команда не выполнилась. Если порт занят до запуска хоста, выберите другой свободный внутренний порт и исправьте весь ENDPOINT/проброс/правило вместе.

**Результат / ограничения:** LISTEN на нужном порту и сообщение «Мир открыт» — локальный сервер готов; внешний вход всё равно проверяет клиент. 0.0.0.0/:: в LISTEN — адрес привязки, не адрес приглашения.

## Как задать сетевой режим

### C1 — Начальная конфигурация

**Точные действия:** В Prism откройте папку Minecraft → config → skycraft.properties в Блокноте. Сохраните копию вне mods. Для DIRECT: join= (пусто), network.mode=DIRECT, network.hostPort=25565, network.advertisedAddress= (пусто). Остальные существующие настройки оставьте. Если файла ещё нет — сначала одиночный запуск SkyCraft.

**Проверка:** Конфиг принадлежит конкретному экземпляру Minecraft. Нельзя редактировать файл из соседнего экземпляра/установки. /join, host, netcheck перечитывают сетевые поля.

### C2 — VPN в режиме туннеля

**Точные действия:** Включите туннель через интерфейс своего VPN; в конфиге SkyCraft network.mode=DIRECT. Для N04/N08 включайте его только на клиенте, хост оставьте базовым. Запишите выбранный сервер, режим, доступ к LAN и порядок включения; секретный ключ/URL подписки не записывайте.

**Проверка:** Трафик следует маршрутам Windows. Если пропал TCP, сравните InterfaceAlias/SourceAddress в Test-NetConnection с базовым прогоном. Это не обязательно ошибка SkyCraft.

### C3 — SOCKS5/HTTP: найти локальный порт

**Точные действия:** В интерфейсе VPN/прокси-клиента откройте настройки локального SOCKS/HTTP/mixed listener: запишите адрес и порт. Часто адрес 127.0.0.1, но порт берётся именно из программы, не из примера. Наличие порта: Get-NetTCPConnection -State Listen -LocalPort ВАШ_ПОРТ. Если программа показывает только системный HTTP-прокси, используйте HTTP_CONNECT.

**Проверка:** PROXY_ENDPOINT — адрес прокси на ПК КЛИЕНТА. ENDPOINT — адрес игрового хоста. Это разные поля и обычно разные порты.

### C4 — SOCKS5

**Точные действия:** На клиенте network.mode=SOCKS5 и network.proxy=АДРЕС_ПРОКСИ:ПОРТ_ПРОКСИ. Имя/пароль, если нужны, только в network.proxy.username/password локально. Системный прокси Windows мод автоматически не импортирует. В /join по-прежнему игровой ENDPOINT. Проверьте /skycraft netcheck ENDPOINT.

**Проверка:** Игровое имя хоста разрешает прокси. Локальная DNS-ошибка Test-NetConnection не доказывает отказ SOCKS5. Не подставляйте 127.0.0.1:порт_прокси в /join вместо адреса хоста.

### C5 — HTTP CONNECT

**Точные действия:** На клиенте network.mode=HTTP_CONNECT и network.proxy=АДРЕС_ПРОКСИ:HTTP_ПОРТ. Затем netcheck игрового ENDPOINT. Если ответ 403/405/407, запишите status_code из events.csv: запрет CONNECT/порта либо запрос авторизации. Используйте реально разрешённый внешний игровой порт, если владелец прокси допускает его.

**Проверка:** Успешный HTTP CONNECT — код 200. Некоторые прокси разрешают только 443; это ограничение прокси. Не меняйте /host на 443 без свободного порта и согласованного проброса.

### C6 — Cloudflare/zapret

**Точные действия:** Запишите в «Условия»: название и версию клиента, режим Cloudflare (DNS либо трафик+DNS), DNS-протокол UDP, профиль zapret, порядок запуска. Меняйте только указанную в сценарии сторону. Наличие warp-svc/winws в процессах не доказывает активный режим.

**Проверка:** N02 — DNS только клиент; N03 — трафик+DNS клиент; N07–N09 добавляют остальные инструменты по порядку. Хост с инструментами отдельно H01/H02.

## Общий прогон по шагам

### 1 — Зафиксировать условия

**Хост:** Заполните строку Run ID во вкладке «Условия прогонов»: свои версии, сетевые инструменты, внутренний порт. Оставьте свой мир Minecraft загруженным. Для теста выберите безопасное место в Skyrim и один Minecraft-мир.

**Клиент:** Заполните ту же строку своими версиями/режимами. Получите ENDPOINT по A2 (LAN), A6–A7 (Интернет) или A8–A9 (IPv6), запишите откуда он получен. Пример 192.168.1.20 не используйте без проверки.

**Что фиксировать:** Один Run ID, понятные роли, записан настоящий адрес и источник адреса.

### 2 — Запустить лог

**Хост:** В Skyrim нажмите T. Команда /skycraft debug start RUN_ID host, где RUN_ID заменён вашим ID, например /skycraft debug start I01_01 host. Enter. Затем /skycraft debug status.

**Клиент:** T → /skycraft debug start RUN_ID client → Enter; затем /skycraft debug status. Для I01_01: /skycraft debug start I01_01 client.

**Что фиксировать:** Запишите путь JSONL из ответа status. Начало UTC есть в JSONL utc. Ошибка записи логгера — STOP, сначала собрать отчёт.

### 3 — Открыть мир

**Хост:** /skycraft host 25565. Дождитесь сообщения «Мир открыт на порту 25565», затем /skycraft debug mark HOST_READY. Проверьте LISTEN по F2. Если внешний порт отличается от 25565, внутри оставьте свой HOST_PORT; в приглашении передайте внешний.

**Клиент:** Не выполняйте /host. Дождитесь от хоста сообщения готовности с ENDPOINT, например реальный IPv4:25565. Не закрывайте своё Skyrim-сохранение.

**Что фиксировать:** Мир хоста открыт, порт слушается. Запишите внутренний и внешний порты в условиях. Хост не должен уходить из своего мира во время теста.

### 4 — Проверить TCP и маршрут

**Хост:** Держите мир открытым; при False у клиента проверьте F1/F2 и A4–A7. Не выполняйте /join в свой мир из этого же экземпляра.

**Клиент:** Для DIRECT выполните Windows-команду из A3/A7/A9 и запишите TcpTestSucceeded, RemoteAddress, InterfaceAlias. В чате: /skycraft netcheck ENDPOINT (замените целиком, например /skycraft netcheck 192.168.1.20:25565). При SOCKS/HTTP основной результат — netcheck, Windows TCP идёт напрямую.

**Что фиксировать:** Успех TCP/netcheck не означает успешный игровой вход. При отказе зафиксируйте текст, UTC, режим, status_code/тип исключения; дальше шаги движения не выполняйте.

### 5 — Войти в мир хоста

**Хост:** Оставаться в мире. Наблюдать появление второго игрока. Когда увидели его: /skycraft debug mark PEER_SEEN. Запишите, виден ли именно второй игрок, а не NPC Skyrim.

**Клиент:** В чате /join ENDPOINT, например /join 192.168.1.20:25565 при этом реальном LAN адресе. Дождаться загрузки мира хоста, затем /skycraft debug mark JOIN_SEEN. /join закрывает ваш собственный Minecraft-мир на время гостевого входа; своё Skyrim-сохранение остаётся локальным.

**Что фиксировать:** У клиента в events.csv world_join с result=remote и elapsed_ms; у хоста два игрока. При ошибке — шаг X1.

### 6 — Проверить движение в обе стороны

**Хост:** Сначала хост проходит 10 Minecraft-блоков вперёд, останавливается, возвращается. Клиент наблюдает. Затем наблюдайте такое же движение клиента. Согласуйте голосом/текстом начало каждого прохода.

**Клиент:** Сначала наблюдать хоста, затем самому пройти 10 блоков и вернуться. После подтверждения обоими: /skycraft debug mark MOVE_BOTH_OK. При откатах/невидимом игроке: /skycraft debug mark MOVE_FAIL и точное описание.

**Что фиксировать:** В «Прогоны» Движение=YES только если оба видят движение друг друга. Отдельно указать дрожание/откаты/задержку. Не мерить ping на глаз.

### 7 — Проверить блоки в обе стороны

**Хост:** В тестовом месте поставьте 3 обычных Minecraft-блока и дождитесь, что клиент увидел все 3. Сломайте их; клиент подтверждает исчезновение. Затем наблюдайте 3 блока клиента. Не используйте TNT/копание Skyrim для первого сетевого теста.

**Клиент:** Подтвердите каждый блок хоста; затем сами поставьте/сломайте 3 обычных блока и дождитесь подтверждения хоста. После обеих сторон: /skycraft debug mark BLOCK_BOTH_OK, иначе BLOCK_FAIL.

**Что фиксировать:** Блоки=YES лишь после установки И удаления в обе стороны. Запишите какой из 12 операций не дошёл, число/позиции блоков и время.

### 8 — Проверить стабильность

**Хост:** Играть число минут из сценария, не выключать хост. Двигаться/строить безопасные блоки, следить за клиентом. Записать фактическое начало/конец и число неожиданных разрывов.

**Клиент:** Играть те же минуты. При каждом разрыве записать время и сообщение. Пинг берётся из клиентского summary.json PingMeanMs/PingMaxMs; клиентские sample.ping_ms пишутся раз в 5 секунд.

**Что фиксировать:** Фактическая длительность не меньше требуемой. Любой разрыв записать, даже если повторный вход сработал. Краткий запуск — PARTIAL.

### 9 — Leave и повторный вход

**Хост:** Не выходить. До leave клиента поставьте один отдельный обычный блок в согласованном месте и оставьте его; после повторного входа клиент должен его увидеть.

**Клиент:** В чате /skycraft debug mark LEAVE_BEGIN → /leave. Дождаться своего Minecraft-мира, /skycraft debug mark OWN_WORLD_OK. Затем /join ТОТ_ЖЕ_ENDPOINT. После входа увидеть оставленный блок и выполнить /skycraft debug mark REJOIN_OK.

**Что фиксировать:** Повторный вход=OK только если свой мир восстановился, затем вернулся мир хоста и оставленный блок сохранился. Чужой блок в своём мире не считать успехом.

### 10 — Остановить лог

**Хост:** /skycraft debug mark RUN_END, затем /skycraft debug stop. Подождите 2 секунды. После этого можно закрывать хост.

**Клиент:** Те же команды и пауза 2 с. Если игра упала — её не перезапускайте поверх логов до сбора отчёта; незавершённый JSONL тоже полезен.

**Что фиксировать:** Последний trace_closed и dropped_events в summary.json. Отсутствие trace_closed фиксировать как незавершённую запись.

### 11 — Собрать ZIP

**Хост:** «Собрать отчёт.cmd» → режим 2. Укажите каталог Minecraft, ТОТ ЖЕ Run ID, роль Host, LAN/Internet, адрес без порта, отдельно порт, свои режимы и результат. Notes: наблюдения без секретов.

**Клиент:** Та же программа: режим 2, тот же ID, роль Client, тот же ENDPOINT (в мастере IP/DNS и порт раздельно). Для IPv6 поле адреса без [] и без :порт. Notes: точный текст сбоя и время.

**Что фиксировать:** Два ZIP в reports рядом с tools. При создании отчётов выберите оба файла с одним ID. Отчёт запуска STARTUP не заменяет размеченный сетевой лог.

### 12 — Заполнить итог

**Хост:** В «Прогоны» внесите факт движения/блоков/разрывов со своей стороны и имя своего ZIP. Оба согласуют PASS/FAIL/BLOCKED/PARTIAL. В «Условия прогонов» зафиксируйте режимы и источник ENDPOINT.

**Клиент:** Из СВОЕГО summary.json: RemoteJoinElapsedMs (нужная попытка), PingMeanMs, PingMaxMs. Впишите имя ZIP клиента. Если поле null/пусто — нет измерения, не ноль. Передайте оба ZIP и заполненную таблицу.

**Что фиксировать:** PASS только по ожиданию выбранного сценария; неизвестные/пропущенные шаги PARTIAL. Недоступная инфраструктура BLOCKED с причиной.

### X1 — Если вход не удался

**Хост:** Зафиксировать, был ли LISTEN и остался ли хост в мире. /skycraft debug mark JOIN_FAIL_HOST, /skycraft debug stop. Сохранить отчёт даже если клиент ничего не увидел.

**Клиент:** Запишите весь видимый текст ошибки. После автоматического возврата в свой мир: /skycraft debug mark JOIN_FAIL → /skycraft debug stop. Если клиент упал — сразу собрать ZIP режима 2 с прежним ID.

**Что фиксировать:** Не проходить шаги 6–9 после неудачного входа. При повторе используйте новый ID, чтобы не смешать причины.

## Откуда брать данные

- **Run ID/UTC:** JSONL поля run_id/utc; run.json CollectedUtc — время сбора, не начало игры. Условия прогонов: Начало UTC; Прогоны: ID.

- **ENDPOINT:** LAN — IPv4Address хоста по A1; Интернет — WAN IPv4 + внешний порт по A4–A7; IPv6 — A8–A9. Условия: Адрес:порт + источник. Скриншот/сведения WAN без пароля можно приложить отдельно.

- **TCP:** В чате netcheck; Windows Test-NetConnection; в JSONL dial_phase, tcp_ready/тип исключения. TCP=OK/REFUSED/TIMEOUT/DNS_ERROR/AUTH_ERROR; при прокси сохранить status_code и этап.

- **Вход, мс:** Клиент summary.json RemoteJoinElapsedMs; конкретный events.csv world_join remote. Вход, мс; если повторный вход — укажите какую попытку выбрали.

- **Ping:** Клиент summary.json PingMeanMs / PingMaxMs. Сред./макс., мс. Это Minecraft latency, не ICMP ping и не FPS.

- **Блоки/движение:** Личные наблюдения обоих + метки MOVE_BOTH_OK/BLOCK_BOTH_OK. YES/NO/NOT_RUN. Сам лог не доказывает, что картинка была правильной.

- **Режимы:** Интерфейсы VPN/WARP/zapret: версии, активный режим, DNS UDP, сервер/профиль без ключей. Условия для каждого ПК отдельно; процессы в отчёте — лишь подсказка.

- **Версии:** installation.json, mod-versions.json, environment в JSONL, Prism → Версии. Условия версий обоих ПК; одно имя JAR не заменяет SHA256.

- **Сбой связи со Skyrim:** skyrim-startup.json: время/факты native логов; JSONL sample.skyrim_linked. Полные SKSE логи — режим 1 с yes. Указать время, меню/Alt-Tab/пауза или активная игра. Старый native лог по LastWriteUtc не приписывать новому запуску.

- **Что отправить:** reports: ZIP host + ZIP client; заполненный XLSX. При проблеме одиночного запуска также installation-*.zip и STARTUP-*.zip. Архивы содержат IP/адаптеры/метки. Пароли/аккаунты/конфиги целиком по умолчанию не собираются. Полные логи предварительно просмотреть.

## Разбор неудачного шага

- **Unknown command:** Проверьте активный JAR по установочному отчёту, один skycraft, версия network.2; английская раскладка и чат T. Сборка/ввод, не маршрутизация. Запишите команду и ответ.

- **Хост не открыл порт:** Открыт ли свой мир? F2 LISTEN? До /host порт занят? Проверить один свободный внутренний порт и обновить endpoint/firewall/проброс согласованно.

- **REFUSED/TIMEOUT:** На хосте F2; затем правильный LAN или WAN, A5 NAT, A6 TCP forwarding, F1 профиль firewall, VPN хоста. REFUSED — получен отказ; TIMEOUT — ответа нет. Код не определяет виновную программу сам по себе.

- **TCP OK, вход не удался:** Версии JAR/MC/Loader, полный текст Minecraft disconnect, этап world_join. Не ставить PASS по TCP. В частности, ошибка авторизации Minecraft — отдельная проблема от транспорта.

- **Ошибка HTTP/SOCKS:** C3: правильный listener/порт; C4/C5: режим, credentials, разрешённый целевой порт. В events.csv найти первый неуспешный dial_phase, status_code и exception_type. Не отправлять пароль.

- **DNS:** Сравнить игровой DNS и тот же IP (E03). При SOCKS/CONNECT DNS цели у прокси, DNS самого прокси — локальный. Локальный nslookup/Resolve-DnsName — вспомогательная проверка, не доказательство DNS на стороне удалённого прокси.

- **Картинка/игрок/блоки:** TCP и вход успешны, но одна сторона не видит движение/изменения. FAIL игрового ожидания; маркировка времени/позиции, оба ZIP, версии/локации обоих Skyrim.

- **Нет JSONL:** Точный каталог экземпляра, /skycraft debug status, ID/role в имени файла. В режиме 1 можно собрать последний AUTO. Для сети неверный ID/роль исправить, затем новая попытка.

- **Закрывается Bethesda:** Сначала vanilla до меню; YS-STARTUP.md и capture-skyrim-startup.cmd. Проверить длинные paths внутри Mods. Не менять VPN-конфиг как лечение обычной игры; сбор дампа только с отдельным согласием владельца ПК.

## Особенности каждого сценария

Для положительных сценариев выполните условия ниже, затем шаги 1–12. Полный повтор шагов для каждого ID есть во вкладке «Сценарии подробно». Для отрицательных S02/S03/E01/E02 действуют их собственные шаги и критерии отказа.

### S01 — Логгер и открытие хоста

**Один ПК / хост или один ПК:** Host: свой мир, DIRECT, /skycraft debug start S01_01 host → /skycraft host 25565. Не выполнять join в себя.

**Клиент:** Второй клиент не нужен. В том же чате /skycraft netcheck 127.0.0.1:25565; F2 LISTEN.

**Ожидание:** PASS: host_open, TCP успех, порт слушается, лог закрывается через debug stop. Совместная игра NOT_RUN.

**Минимум:** 2 минут. **PASS:** Хост открыл порт; TCP доступен; отчёт содержит host_open, probe_result и trace_closed.

**Ограничение:** PARTIAL для мультиплеера: второго игрока нет.

### S02 — Закрытый порт

**Закрытый порт / хост или один ПК:** Один ПК: проверить отсутствие LISTEN на 25566: Get-NetTCPConnection -State Listen -LocalPort 25566 -ErrorAction SilentlyContinue. Если занят — другой свободный порт.

**Клиент:** /skycraft debug start S02_01 client → /skycraft netcheck 127.0.0.1:25566. Затем /join 127.0.0.1:25566; дождаться сообщения и своего мира.

**Ожидание:** PASS обработки ошибки: явный отказ/timeout в пределах настроенного timeout + небольшой запас, клиент не висит, вернулся свой мир. JOIN_FAIL, debug stop, ZIP Client.

**Минимум:** 2 минут. **PASS:** Понятный отказ TCP; игра отвечает на ввод. PASS означает ожидаемый отказ, не успешный вход.

**Ограничение:** Проверяется обработка ошибки netcheck, не /join в свой же мир.

### S03 — Недоступный прокси

**Недоступный прокси / хост или один ПК:** Второй ПК не нужен. Сохранить исходный config; убедиться, что 127.0.0.1:25566 не слушается.

**Клиент:** На клиентском экземпляре network.mode=SOCKS5, network.proxy=127.0.0.1:25566; debug start S03_01 client; netcheck известного рабочего ENDPOINT или 127.0.0.1:25565. Повторить отдельным ID с HTTP_CONNECT.

**Ожидание:** PASS: контролируемый отказ подключения к прокси; нет скрытого обхода DIRECT. После теста вернуть исходный config. Не использовать этот ENDPOINT как тест двух игроков.

**Минимум:** 3 минут. **PASS:** Отказ от прокси записан; зависания игры нет; восстановленный DIRECT снова проходит S01.

**Ограничение:** Неправильный прокси намеренный; PASS = корректная ошибка.

### S04 — Настоящий пакет входа через прокси

**Разработческий smoke / хост или один ПК:** Это автоматизированная проверка в исходниках, не на ПК друга. В source: powershell -ExecutionPolicy Bypass -File tools/dev.ps1 -Action NetworkSmoke.

**Клиент:** Друг без JDK/исходников оставляет S04 NOT_RUN. Тест запускает изолированный настоящий Minecraft, тестовый HTTP proxy и закрывается автоматически.

**Ожидание:** PASS разработчика: network-smoke-result.txt=PASS, HTTP 200, исходный адрес в handshake, события канала/trace_closed. Не ставить PASS мультиплееру.

**Минимум:** 2 минут. **PASS:** network-smoke-result.txt = PASS; JSONL содержит channel_active, HTTP 200 и trace_closed.

**Ограничение:** Автоматически проверено 03.10.2026; мир и второй игрок не проверяются.

### L01 — Базовая совместная игра

Оба: VPN, WARP, zapret выключены; DIRECT. Один физический роутер, A1–A3.

Хост открыть 25565; клиент взять LAN IPv4 именно хоста.

**Минимум:** 5 минут. **PASS:** Оба видят движение и изменения блоков; 5 минут без неожиданного разрыва; /leave возвращает свой мир.

**Ограничение:** Основная точка сравнения. Квесты и NPC Skyrim сюда не входят.

### L02 — Смена хоста

Сначала L01 PASS. Поменять роли и получить новый LAN IPv4 по A1 на новом хосте.

Предыдущий хост закрывает свой сервер и становится клиентом. Не использовать прежний endpoint.

**Минимум:** 5 минут. **PASS:** Успех при обеих ролях, отдельные архивы каждого ПК.

**Ограничение:** Помогает обнаружить различия firewall/адаптеров/установки.

### L03 — Переподключение и уход хоста

Сначала L01 PASS; роли/адрес/режимы прежние.

Особенно проверить шаг 9: клиент leave → свой мир → повторный join; оставленный блок у хоста виден.

**Минимум:** 5 минут. **PASS:** Понятный разрыв, без вечного автоповтора; повторный ручной вход работает.

**Ограничение:** debug start повторяется после перезапуска; сборщик объединит файлы одного ID/роли.

### I01 — Разные сети, прямой вход

Разные сети. Оба DIRECT без инструментов. Хост: A4–A7 либо смена ролей, если входящий адрес есть только у друга.

Клиент использует WAN IPv4 + внешний порт; TCP проверяет из другой сети. При CGNAT без доступного узла BLOCKED.

**Минимум:** 10 минут. **PASS:** Общий цикл проходит и сохраняются два отчёта.

**Ограничение:** При отсутствии доступного порта: BLOCKED, указать NAT/CGNAT. Ретранслятор ещё не реализован.

### I02 — IPv6

Оба имеют рабочий глобальный IPv6, DIRECT; выполнить A8–A9.

У хоста разрешён входящий IPv6 TCP; клиент использует [адрес]:порт, а PowerShell — адрес без скобок.

**Минимум:** 5 минут. **PASS:** Вход и 5 минут совместной игры проходят.

**Ограничение:** Если IPv6 отсутствует: BLOCKED; не заменять его локальным адресом.

### N01 — zapret на клиенте

Сначала I01/L01 PASS. Хост остаётся базовым. Клиент включает только zapret, network.mode=DIRECT.

Записать профиль/версию zapret; IP/порт и остальные условия оставить базовыми.

**Минимум:** 5 минут. **PASS:** Сравнить с базовым прогоном; общий цикл, нет обрывов.

**Ограничение:** Точный профиль важнее одного факта наличия winws.

### N02 — Cloudflare, только DNS на клиенте

Сначала базовый PASS. Только клиент: Cloudflare DNS-only, без перенаправления трафика; DIRECT.

Записать фактический режим DNS. Прочие инструменты выключены.

**Минимум:** 5 минут. **PASS:** Оба адреса работают; отдельно сравнить отказ DNS и отказ TCP.

**Ограничение:** Нет DNS-имени — прогон по имени BLOCKED; по IP всё ещё полезен.

### N03 — Cloudflare трафик + DNS (UDP)

Сначала базовый PASS. Только клиент: Cloudflare трафик+DNS, выбранный DNS-протокол UDP; DIRECT.

Записать режим в интерфейсе Cloudflare. Успех одного TCP не доказывает, что DNS шёл UDP.

**Минимум:** 10 минут. **PASS:** Установление соединения, блоки в обе стороны, 10 минут без разрывов.

**Ограничение:** Результат относится к этому профилю и этой сети.

### N04 — VPN-туннель на клиенте

Сначала базовый PASS. Только клиент: один VPN-туннель; DIRECT по C2.

Если LAN пропала, отметить настройку Allow LAN VPN. Хост/адрес не менять.

**Минимум:** 10 минут. **PASS:** Игра следует маршрутам VPN, общий цикл проходит.

**Ограничение:** DIRECT использует маршруты Windows; системный прокси отдельно не импортируется.

### N05 — Явный SOCKS5 VPN-клиента

Сначала базовый PASS. Только клиент: включён SOCKS listener VPN-клиента; C3–C4.

Записать реальный порт, network.mode=SOCKS5. Хост по-прежнему открыт базовым способом.

**Минимум:** 5 минут. **PASS:** Удалённый DNS через прокси; TCP и игровой вход проходят.

**Ограничение:** Локальный LAN IP хоста может быть недоступен через удалённый VPN-прокси: BLOCKED/маршрут, не ошибка авторизации.

### N06 — Явный HTTP CONNECT VPN-клиента

Сначала базовый PASS. Только клиент: HTTP/mixed listener VPN-клиента; C3+C5.

network.mode=HTTP_CONNECT. При запрете CONNECT сохранить HTTP код; при невозможности у прокси — BLOCKED, не выдумывать 443.

**Минимум:** 5 минут. **PASS:** В JSONL HTTP 200; вход в мир и изменения блоков проходят.

**Ограничение:** HTTP 403/407 фиксировать отдельно. CONNECT может быть запрещён на игровом порту.

### N07 — zapret + Cloudflare

Сначала N01/N03. Только клиент: zapret, затем Cloudflare traffic+DNS UDP; DIRECT.

Зафиксировать порядок включения и профиль обоих инструментов; хост базовый.

**Минимум:** 10 минут. **PASS:** Сравнить с N01 и N03; 10 минут без разрывов.

**Ограничение:** При изменении профиля — новый прогон.

### N08 — zapret + Cloudflare + VPN-туннель

Сначала отдельные N01/N03/N04. Только клиент: zapret → Cloudflare traffic+DNS UDP → VPN tunnel; DIRECT.

Все три активны; записать порядок и выбранный VPN-сервер. Новый снимок маршрутов перед join.

**Минимум:** 15 минут. **PASS:** Вход и стабильность 15 минут; причины сбоев сравнить с одиночными режимами.

**Ограничение:** Основная комбинация пользователя. Совместимость ещё не подтверждена.

### N09 — Все инструменты + явный прокси

Сначала N05/N06 и N07. Только клиент: zapret + Cloudflare traffic/DNS UDP + VPN в режиме системного прокси.

По реальному listener выбрать SOCKS5 либо HTTP_CONNECT; Windows system proxy сам по себе модом не используется. Два транспорта — две попытки/ID.

**Минимум:** 15 минут. **PASS:** Каждый транспорт оценивается отдельно; 15 минут игры на каждом доступном режиме.

**Ограничение:** Не выводить результат SOCKS5 из результата HTTP CONNECT.

### H01 — Инструменты на хосте

Сначала базовый PASS. Клиент остаётся базовым DIRECT. Хост включает zapret + Cloudflare traffic/DNS UDP.

Заново проверить входящий адрес/порт по A7/A9 с клиента. Исходящий внешний IP хоста может измениться; не подменять им WAN без проверки.

**Минимум:** 10 минут. **PASS:** Проверить публикацию порта, вход клиента и стабильность каждого варианта.

**Ограничение:** Выходной прокси хоста не публикует его сервер; VPN может закрыть входящий маршрут.

### H02 — Инструменты на обоих ПК

Сначала H01 и N08/N09. На ОБОИХ требуемая полная комбинация. Хост с VPN может потерять входящий маршрут.

Сначала проверить вход TCP, затем игровой поток. Если VPN хоста не предоставляет входящий порт и базовый WAN перестал доступен — BLOCKED инфраструктуры; записать точный режим.

**Минимум:** 15 минут. **PASS:** 15 минут, изменения в обе стороны, успешный /leave и повторный вход.

**Ограничение:** Если хост недоступен из-за NAT/маршрута: BLOCKED для приёмки, приложить диагностику.

### E01 — Неправильный пароль прокси

**Неверная авторизация прокси / хост или один ПК:** Хост остаётся базовым и доступным. Нужен ВАШ тестовый прокси, который требует auth; без такого прокси BLOCKED.

**Клиент:** Временно указать ошибочный пароль для своего прокси в client config, не угадывать чужие пароли. debug start E01_01 client → netcheck рабочего ENDPOINT → join.

**Ожидание:** PASS: явная AUTH_ERROR/HTTP 407/SOCKS отказ, нет скрытого DIRECT fallback, клиент остаётся в своём мире. Вернуть пароль; секрет не писать в Notes/таблицу.

**Минимум:** 3 минут. **PASS:** Отказ авторизации без зависания; восстановление пароля возвращает работоспособность.

**Ограничение:** Без прокси с авторизацией — BLOCKED.

### E02 — Отмена подключения

**Отмена соединения / хост или один ПК:** Хост/прокси тестовый и подконтрольный вам. Нужна цель, которая принимает TCP и задерживает ответ; случайные чужие адреса не использовать. Без fixture BLOCKED.

**Клиент:** debug start E02_01 client → join тестового ENDPOINT через этот прокси; на экране соединения нажать Отмена раньше timeout. Записать UTC. Проверить возврат в свой мир.

**Ожидание:** PASS: отмена закрыла сокет/мост и вернула свой мир; новая попытка не использует старый результат. Затем debug stop и отчёт. Пустой закрытый порт — другой сценарий S02.

**Минимум:** 3 минут. **PASS:** Поздний ответ не заменяет текущий мир; повторный вход работает; записать время отмены.

**Ограничение:** Если соединение завершилось до нажатия — NOT_RUN, не PASS.

### E03 — DNS-имя и IP одной цели

Сначала рабочее соединение. Нужна собственная DNS-запись имени хоста, которая указывает на тот же публичный IP; без имени BLOCKED.

Отдельные прогоны для IP и DNS имени при DIRECT, затем выбранном прокси. IP, порт и роли сохраняются; нет SRV поиска, порт всегда явный.

**Минимум:** 5 минут. **PASS:** Выделить локальный DNS сбой в DIRECT и DNS/маршрут прокси в других режимах.

**Ограничение:** Специально ломать DNS Windows не требуется; отсутствие имени — BLOCKED.

### E04 — UDP недоступен

Не менять глобальные сетевые настройки ради теста. Нужна уже существующая среда/профиль, где игровой UDP недоступен.

TCP Minecraft должен пройти; запишите как подтверждали отсутствие UDP. Если не можете подтвердить ограничение UDP — PARTIAL/BLOCKED, не PASS.

**Минимум:** 5 минут. **PASS:** Проверить Minecraft TCP при этих условиях, отметить возможный отказ самого VPN/DNS.

**Ограничение:** Без подтверждённого ограничения — BLOCKED. STR UDP этим тестом не проверяется.

### E05 — Переключение сети во время игры

Сначала N04 или N05/N06 PASS. Оба знают какой VPN-профиль клиента будет сменён.

После входа и 60 с игры: mark SWITCH_BEGIN, сменить профиль через VPN UI, записать UTC. Дать клиенту до 30 с на явный разрыв/восстановление; при разрыве повторить join, отметить SWITCH_REJOIN. Смена TCP-маршрута может разорвать соединение.

**Минимум:** 5 минут. **PASS:** Смена маршрута может оборвать TCP; требуется понятный разрыв и работоспособность ручного входа после стабилизации.

**Ограничение:** Непрерывность TCP при смене маршрута не обещается.

## Итоги и отправка

PASS — все ожидания данного сценария выполнены. FAIL — ожидание нарушено. BLOCKED — нет необходимых условий (например публичного входящего адреса). PARTIAL — проверена только часть, не выдержана длительность или не подтверждена нужная сетевая среда. NOT_RUN — не запускали.

Передайте заполненную XLSX и два ZIP с одним ID (host/client). При проблеме установки дополнительно installation-*.zip. Для запуска без debug start: «Собрать отчёт.cmd», режим 1, последний AUTO JSONL будет собран автоматически. Полные игровые логи включаются только по выбору yes; они могут содержать чат и имена. Конфиг с паролями и accounts.json не отправляйте.
