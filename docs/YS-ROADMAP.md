# Доработки SkyCraft YS

Исходная версия: chasmlol/SkyCraft 0.1.2, commit
`bfcaf178524b92c2cdeb88e4ce0f13ef9ded6f32`.

## 1. Сеть без e4mc

Пожелания пользователя:

- Хостом игры предпочтительно служит компьютер одного из игроков.
- Бесплатная внешняя инфраструктура допустима; платный VPS не выбран.
- Пользователь предпочитает не заводить сторонний аккаунт; Tailscale исключён из выбранного решения.
- Соединение предназначено только для SkyCraft.
- Проверить работу с zapret-discord-youtube, Cloudflare One Client
  (трафик и DNS UDP), VPN-туннелем и системным прокси, включая сочетания.

Сначала проверить прямой доступ к серверу Minecraft и явно заданные адреса.
Затем выбрать транспорт, обнаружение хоста и резервную ретрансляцию.
Наличие сервера игры у игрока само по себе не решает недоступность входящих
соединений при CGNAT. У бесплатного посредника проверить ограничения и
доступность, прежде чем брать его за основу.

Предварительный вариант для исследования: прямое соединение там, где оно
работает; резервное соединение через TLS на TCP 443 с явно настраиваемыми
HTTP CONNECT/SOCKS-прокси. Конкретный протокол и поставщик ещё не выбраны.
TLS/443 сам по себе не гарантирует прохождение фильтрации.

Точки входа в 0.1.2: `MirrorWorld.java`, `DiscordPresence.java`,
`fabric/build.gradle`, `skse/src/Launcher.cpp`, `tools/package.ps1`.
Проверить также все ссылки на e4mc и обработку команд подключения.

Приёмка: два настоящих клиента; вход, выход, повторное подключение;
несколько игроков; LAN, разные NAT, CGNAT, недоступный UDP, проблемы DNS,
каждый указанный VPN/прокси и необходимые сочетания. Записать задержку,
обрывы, восстановление и понятность ошибок. Этот этап синхронизирует Minecraft;
совместный мир NPC/квестов Skyrim рассматривается в будущем этапе 3.

## 2. Автоматическая конвертация добычи

Подобранный предмет Skyrim конвертируется по конфигурируемой таблице.
Предмет без соответствия остаётся в Skyrim. Начальный черновик соответствий:
железная руда → minecraft:raw_iron; железный слиток → minecraft:iron_ingot.
Это предложения для согласования; количества и остальные строки не заданы.

Предварительно исключать квестовые и уникальные предметы из автообмена.
Перед реализацией согласовать охват: предметы с земли, контейнеры, тела,
торговля, награды; поведение при полном инвентаре; зачарованные и краденые
предметы. Начать с небольшого набора обычных ресурсов.

Технические условия: устойчивые ключи таблицы (plugin + local FormID),
событие на стороне Skyrim, сообщение через протокол и выдача на серверной
стороне Minecraft. Обязательны идентификатор операции, подтверждение,
защита от повторной выдачи и определённое восстановление после сбоя/загрузки.
Изменения протокола делать одновременно в C++ и Java.

Приёмка: одиночный предмет, стопка, неизвестный предмет, квестовый предмет,
полный инвентарь, отключённый Minecraft, повтор сообщения, сохранение и
загрузка каждого процесса. Не допускать тихой потери предметов и дюпов.

## 3. Будущая интеграция со Skyrim Together Reborn

Пользователь хочет в дальнейшем проходить вместе квесты Skyrim и играть
в общем мире. Интеграция запланирована как отдельный этап; её реализуемость
и совместимость ещё не подтверждены.

Предлагаемое распределение ответственности: Skyrim Together Reborn управляет
синхронизацией Skyrim, Fabric — состоянием Minecraft, а адаптер связывает
участников двух сессий. Нужно определить единственный источник каждого
изменения, чтобы не удваивать персонажей, урон, добычу и изменения инвентаря.
Конвертацию предметов проектировать с учётом будущего подтверждения операций
владельцем/сервером Skyrim-сессии.

До окончательного выбора сетевого решения проверить транспортные требования
STR. Работоспособность туннеля для Minecraft сама по себе не подтверждает
его пригодность для STR; желательно общее подключение для пользователя,
но технически могут понадобиться два канала.

Сначала провести отдельный прототип: два клиента с обоими модами, появление
игроков, движение/камера, бой, переход в интерьер, небольшой квест,
подбор/конвертация предметов, переподключение, сохранение/загрузка.
Особенно проверить, как SkyCraft управляет игроком Skyrim и как STR
синхронизирует того же игрока. Физическое разрушение мира SkyCraft также
нужно проверить на обеих машинах.

Проверка 2026-10-03: [релиз STR 1.8.1](https://github.com/tiltedphoques/TiltedEvolution/releases/tag/v1.8.1)
явно заявляет поддержку Skyrim SE 1.7.104 и SKSE 2.2.6+. Это уточняет устаревший
номер 1.6.117X в FAQ. Наша версия игры подходит по заявлению разработчиков;
совместимость именно с SkyCraft ещё не проверена.

Сервер STR использует UDP 10578: [официальный образ сервера](https://hub.docker.com/r/tiltedphoques/st-game-server).
Обычный TCP CONNECT для Minecraft этот канал не переносит. В будущем общем
транспорте понадобится отдельная передача датаграмм с привязкой к игроку,
ограничением размеров и таймаутами; при UDP-over-TLS измерить задержку под нагрузкой.

Исходники STR: [TiltedEvolution](https://github.com/tiltedphoques/TiltedEvolution).

## Порядок работы

Сетевой прототип 0.1.2-ys.network.2: команды открытия хоста и диагностики,
SOCKS5/HTTP CONNECT, явный адрес приглашений, отмена и возврат в свой мир.
e4mc убран из Gradle и новых пакетов. Подробности: [YS-NETWORK.md](YS-NETWORK.md).
Добавлены автоматический JSONL-логгер, Windows-сборщик локальных отчётов и
[таблица с инструкцией тестирования](YS-TESTING.md).
Доступен один компьютер; проверка между разными сетями ждёт второго игрока.

Наблюдение SKY-001, 03.10.2026: пользователь уточнил, что телепорт в начало
локации замечен при выпадении из мира Minecraft; пользователь допускает
связь с завершением восстановления. В ручном S02_01 после неудачного `/join`
собственный мир восстанавливается, но точный момент телепорта не установлен.
JSONL подтверждает отказ и повторный вход в локальный мир; координаты до/после
не записывались, поэтому причина смещения пока не доказана. Не считать это
подтверждённой нормой исходного мода. Проверить сохранение позиции при отказе,
отмене, `/leave` и повторном входе; воспроизвести на исходной 0.1.2 отдельно.
Существующий `SkyClient` после создания нового объекта игрока заново ставит
его в координаты, переданные Skyrim; этот участок относительно 0.1.2 не менялся.

1. Воспроизводимая сборка исходной 0.1.2 и отдельное тестовое окружение.
2. Проверка версии STR и его сетевых требований; короткий сетевой прототип
   для наиболее проблемного соединения.
3. Выбор транспорта по результатам прототипа.
4. Конвертация нескольких ресурсов с тестами протокола и восстановления.
5. Расширение таблицы и интеграционные проверки в игре.
6. Отдельный прототип совместимости со Skyrim Together Reborn, затем адаптер.
