# Исправление загрузки сохранений: network.6, комплект r7

Комплект **r6 отозван**: его SkyCraft.dll вызывает вылет Skyrim Anniversary Edition при первой загрузке сохранения. Пользоваться DLL из r6 нельзя. Комплект r7 содержит исправленную DLL; Minecraft остаётся версии 0.1.2-ys.network.6, настройки сети и код подключения не меняются.

## Причина и исправление

В дампе установленной r6 стек приводит к `Actor::IsEssentialDown` → `SkyrimTakeover` → `PerFrame`. В закреплённом CommonLib эта функция имеет `RELOCATION_ID(48460, 0)`: адрес для AE отсутствует. При появлении персонажа мод вызывал нулевой адрес. Это ошибка обновления DLL; данный сбой не свидетельствует о повреждении сохранений.

В r7 проверка читает состояния bleedout и knockdown/get-up из ActorState через встроенные методы без обращения к адресам игровых функций. Перед каждой native-сборкой теперь проверяются прямые вызовы пяти Actor-функций, для которых в закреплённом CommonLib отсутствует AE-адрес. Это ограниченная проверка исходников, а не доказательство исправности всех игровых адресов.

В первой строке свежего SkyCraft.log исправленная DLL сообщает **0.1.2-ys.network.6-r7**. Старый лог r6 сообщал только **0.1.2**. Контрольная сумма DLL также указана в package-manifest.json комплекта.

## Установка другу

1. Скачать **SkyCraft-AutoTests-0.1.2-ys.network.6-r7.zip**. Старый архив без r7 в имени не использовать.
2. Закрыть Skyrim и экземпляр SkyCraft в Prism. Распаковать **весь** ZIP, например в папку на рабочем столе. EXE, папки tools/native и package-manifest.json должны остаться вместе. Из ZIP помощник не запускать.
3. Запустить SkyCraft-Клиент.exe; нажать **Обновить мод**. Помощник предложит каталог Minecraft: это папка с mods, config и logs. Проверить её через Prism: правой кнопкой по экземпляру SkyCraft → папка Minecraft.
4. Если помощник попросит SkyCraft.dll, открыть MO2 → левый список модов → правой кнопкой по установленному основному SkyCraft → **Открыть в проводнике** → SKSE → Plugins. Выбрать находящийся там SkyCraft.dll. Файл из распакованного комплекта выбирать нельзя: нужен установленный файл, который помощник заменит.
5. Дождаться завершения обновления. Установщик проверяет DLL/JAR по контрольным суммам и сохраняет предыдущие файлы в SkyCraft-YS-backups рядом с папкой Minecraft. Настройки и сохранения не перезаписываются.
6. Запустить SKSE из MO2. Сначала выполнить короткую проверку загрузки ниже. После её успеха переходить к ИГРОВЫЕ-ПРОВЕРКИ.html и совместным тестам.

## Проверка загрузки без друга

1. В меню Skyrim выбрать **Загрузить** и открыть отдельное тестовое сохранение, которое вылетало на r6. Основное сохранение не перезаписывать.
2. После появления локации дождаться HUD Minecraft, затем минуту пройтись, повернуть камеру и прыгнуть. Записать: загрузилось ли сохранение, появился ли HUD, работает ли управление, были ли падение/телепорт/вылет.
3. Через меню игры загрузить ещё одно из ранее вылетавших сохранений. Повторить минуту проверки. Проверять именно повторную загрузку в том же процессе Skyrim.
4. Выйти в главное меню, закрыть Skyrim обычным способом, снова запустить SKSE через MO2 и загрузить одно из этих сохранений. Проверить HUD и движение ещё раз.
5. Если какой-то шаг не выполнялся, отметить **Не проверено**. Если игра вылетела, записать номер шага, примерное время и момент вылета; повторно запускать игру до сбора свежего лога не нужно.

Локальный лог: папка **Документы → My Games → Skyrim Special Edition → SKSE → SkyCraft.log**. Дамп при вылете: **SkyCraft_crash.dmp** в той же папке. Лог перезаписывается новым запуском, поэтому при ошибке сначала собрать отчёт. Дамп содержит фрагменты памяти процесса; передавать его только для диагностики, не публиковать на GitHub.

Для обычных игровых проверок после успешной загрузки использовать **SkyCraft-Без-друга.exe → Игровой тест до остановки → Остановить и собрать отчёт**. Если Skyrim вылетает до возможности включить этот сценарий, на текущем ПК логи соберёт Codex; на другом ПК сохранить указанные SkyCraft.log и SkyCraft_crash.dmp сразу после вылета.

## Границы проверки

10 октября 2026: RelWithDebInfo-сборка r7 и проверка прямых Actor-вызовов прошли. На текущем ПК пользователь подтвердил успешную загрузку двух ранее вылетавших сохранений, HUD Minecraft и движение; свежий лог содержит версию r7 и `puppet on`. Перезапуск процесса с последующей загрузкой отдельным тестом пока не подтверждён.

Исправление касается установленной причины вылета при загрузке на AE. Проверка загрузки сохранений отдельно от проверки удара тролля/великана: исходный вылет при сбивании с ног требует собственного игрового теста G07. Java-компонент и протокол общей памяти в r7 не изменялись.
